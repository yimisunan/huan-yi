# 场景与正式连续互动规范

本文件是连续互动的契约入口。正式首页支持两代程序资料交付：v1（`material_delivery=program_inline_v1`）按当前任务租约将冻结packet与必要补读源一次性直送用户消息；v2（`program_prefix_v2`）由 `story_compiler.py` 将全局规则与当前场景人设/关系知情边界只读投影到专用角色卡的冻结前缀（Zone 0 / Zone 1，仅 SHA-256 变化时同步），每轮用户消息仅提交增量 delta，以最大化隐式前缀缓存命中。两种交付均由插件核对已保存用户消息，服务端核验独立交付记录、任务租约、来源指纹、前缀指纹和会话回执。模型完整理解已交付正文，不为证明读取而再次逐段读packet，也不得把程序读取伪装成模型工具读取。此交付证明的是程序读到并送达了正文，不证明模型正确理解、遵守全部人物设定或推理正确；原有输出、剧情、信息边界和结算校验照常执行。超过2MiB时拒绝交付，不截断。

旧正式桥接和实验入口仍按packet.path/read_ranges实际使用只读工具取得全部正文；核对真实返回末行，截断缩小范围补齐，纯尾空白不计缺读。程序交付路径若确需更早历史，也按当前许可索引与精确原文范围补读。来源指纹、旧聊天及失败草稿均不能代替本轮正文。只允许当前任务列出的只读工具与路径；grep_code只定位、不算正文覆盖；目录遍历和写工具不允许。

## 正式剧情与演播

正式首页以文字沉浸交互为核心，依据本次人物、世界规则、实际存档、已接受历史与玩家选择主动推演剧情。人物带着各自的当下事务、私心与关注点行动，玩家上一行动应得到可感知的回应、后果、暗流破绽或新信息位移；**不再硬性限制旁白/对白字数或节点数量**——重要场景、情感交锋、商战博弈与亲密场面可按文学呼吸充分写透，日常快节奏承接亦可干脆短答；唯一约束是反注水、反重复客套。若后端动态概率导演引擎（Entropy RNG，配置见《互动运行配置.json》与《世界变故库.json》）当轮暗骰命中并注入 `surprise_directive`，前台将其作为客观外部变数自然织入剧情，绝不泄露概率、骰子或系统词。

停顿应落在实际需要玩家回答、新信息或破绽产生分歧、外部变数落地、原行动结果已呈现或继续会替玩家做新关键决定之处。每段结束交 decision，玩家点按演播完本段后才显示 A/B/C 与自定义；播放、回看、静音与立绘不产生新行动，不后台自动续写。尊重主权、括号显形、主体感和角色边界，不替玩家编造台词、承诺、经历、意图升级或关键决定。

在双阶段流式模式（`dual_stream_v2`）下，主模型专注前台剧场正文与段末抉择，按 `[N]` / `[A:姓名]` / `[D:姓名]` 与 `---DECISION---` 逐行流式演播；前端默认采用沉浸幕布等待结算完成后揭幕（亦可切换即时流式预览，预览仅驻留服务端内存，绝不写入 `RoundStore` 或正式存档，若结算失败、取消或拦截将立刻撤回并退还预扣）。前台演播结束后由后台结算通道（默认 Operit 2 `SUMMARY` 槽，思考策略默认 `auto` 智能自适应：首轮极速免思考，校验未通过重试第 2～3 轮时自动启用思考并回传精准错误修复提示，可选 `off`/`on`）无状态提取 `operation` / `handoff` / `checks` / `resolution` / `quality_flags`，经程序解析器与硬红线守卫合成为标准正式结果，仍由唯一 `RoundStore` 事务原子落盘；可重试的结算字段错误仅原地重试后台结算，不重跑前台剧情。单阶段模式（`single_prefix_v2`）继续直接输出单个合法裸JSON。

messages 按顺序承载完整段落，项只有 kind、speaker、text。dialogue 为实际在场角色说出口的纯对白，action 为归属明确的人物动作，narration 为必要叙述；对白和动作严格分开。非主角 dialogue 的 speaker 必须在 scenario.cast 内，**严禁输出场外人物对白**；关于 `[D:徐志北]`（徐志北永久静音，严禁 Fish 标签）：在默认「忠实演绎」（`protagonist_style=faithful`）下，每幕开场须有 1～2 句 `[A:徐志北]`/`[N]` 具身落位，中段保留自然微反应，且允许最多 2～3 句（硬上限 3 句）严格贴合玩家本轮原意图的简短 `[D:徐志北]`（单句 ≤40 字、严禁代做新决定/新承诺/意图升级）；在「仅动作感官」（`protagonist_style=silent`）下严禁输出 `[D:徐志北]`，玩家提问仅在 `[A:徐志北]`/`[N]` 中以间接动作概括承接。**`[D:姓名]` 纯台词锁**：只放开口说出的纯台词（及可选合法 Fish 英文方括号标签、`｛表层台词｜真实潜台词｝`），**严禁加外层引号 `“...”`**，**严禁夹带“她端起杯子抿了一口：”等第三人称动作/神态旁白**（动作一律独立写为 `[A:姓名]`，且 `[A:...]` 与 `[N]` 严禁写 Fish 标签；双端流式解析器同步提供动作-引号自动拆分兜底）。action 可为在场角色或徐志北，玩家动作仅限原输入明确授权的行为及必要承接；narration 的 speaker 为空串。text 非空、去空白不超过 4000 字符（仅作传输防呆保护，不作为写作字数限制）。最多 1000 节点仅为传输保护，不把连贯段落切碎成一次次点击。

## 正式输出与行动

单阶段正式入口（及双阶段合并后的规范结果）均只接受合法结构，顶层键恰为 messages、decision、operation、handoff、checks、resolution。decision 恰含 prompt 和 options；prompt 为不超过 300 字的具体当前分歧或悬念；options 恰为依序三项，每项必填 id 与 text（id 依次 A/B/C，text 不超过 500 字），并可选包含受控转场字段 `operation`（仅限合法 `{"code":"move_player","destination":"<非当前登记地点>"}`，无转场时省略 `operation` 键，运行层亦对误填的 `""` 做空值归一化；流式输出通过 `A[MOVE:登记地点]: ...` 或句尾 `[MOVE:登记地点]` 显式声明，由程序校验并由前端展示去向徽标与原样透传，防篡改核验与本段严格一致）。命名与三轴推进职责沿 lore.命名锁，由程序显示固定名称；正文不重复列选项、不提前代执行。选项须符合当前人物/地点/物品及意图边界，不能因价格高就承诺好结果或强塞升级。正式桥接传输中 operation 无操作时明确为 ""（两个双引号），有操作时为下列合法对象；内部执行器的无操作值为 null，桥接仅在整份 JSON 合法解析后将 operation 的空字符串转换为 null，兼容既有合法 null。不能省略值或把冒号后留空。handoff 无待处理时为 ""，否则是不超过 300 字的说明。checks 恰含 intent、knowledge、action、pace 四条具体单行依据，分别说明玩家意图、知情、操作一致性以及本段位移与交还控制权的理由；不用“已读取”“通过”“同上”代替依据。程序身份、消耗、指纹、审计长表、SYSTEM_LOG 与 L1 不混入正文，选项只放 decision。

登记操作如下：

- move_player：对象只含 code 与 destination；destination 须在互动运行配置 locations 中；地点原名及 location_aliases 由程序统一解析（如「家/主宅」→徐家主宅、「公寓」→市中心顶层公寓、「画室/校外画室」→工作室）。可由点击带显式 `[MOVE:地点]` 的固定选项、前端快捷移动或自由输入明确当下前往触发；否定、稍后计划、选择或多目的地不自动移动。仅玩家本人移动，不自动搬动其他人物。到达后的回应限目的地人物。不得补写未发生的通话、邀请或获得进入私密空间的许可；实际边界和拒绝仍由人物及现场依据表现。
- transfer_item：对象含 code、item_id、recipient 及可选 quantity（正整数，默认整组交付）；交付已持有、仓库中、可赠予（`giftable != false`；宿主体力消耗品不可赠予）的道具，接收人必须实际同地（含实际回返在场的徐承邺）。整组交付时移入 `已交付道具区`，部分交付时扣减随身库存并新增已交付记录；后续商城重购同名道具不会覆盖已交付记录。
- use_item：对象含 code、item_id 与可选 target（在场人物或 `室内氛围`）；针对 `consumable_target`（消耗品，如热感精油/微醺香薰/桃味软糖）扣减数量并即时挂载对应 `[buff]`（本回合即享减损/协同效果，回合末自然递减至完整持续回合），针对 `reusable_tool`（反复工具，如蒙眼丝带与玉石滚轮）保留库存不消耗，由正文自然演绎现场互动。
- deploy_item：对象含 code、item_id、spot（1～40 字安装点位）与可选 hidden（布尔，默认 true）；针对 `deployable_device`（可部署装置，如针孔摄像头/隐蔽录音器），将 1 件装置从随身移入 `已部署装置区` 并绑定当前地点、点位、隐蔽标记与安装时间。
- retrieve_item：对象含 code 与 item_id；玩家须与目标已部署装置处于同一地点，执行后从 `已部署装置区` 拆回至随身活跃库存。
- inspect_deployed：对象含 code 与 item_id；可在任意地点远程查看已部署装置的实时画面或拾音（后端自动注入装置所在地的实时在场人物 `remote_cast`）。远程画面/监听内容须严格用 `[N]` 与 `[A:徐志北]` 叙述（远程人物声响用引号写在 `[N]` 中），严禁输出 `[D:远程人物]` 以维持在场说话人锁。

任务 packet 中 operation.requested 非空时，操作已按当前版本预检，模型保持该对象不变，写同一操作的现场反应；若有现场拒绝或缺少通行/交付条件，operation 按传输约定返回空字符串并在 handoff 说明，正文保留尚未执行的实际状态，不强迫人物接受。自由输入可提议一个有玩家明确原文依据的登记操作；多项、歧义、无权限、未持有物、未登记操作以及未定义秘密披露返回待处理或澄清，正文不宣称已执行。一次不执行多个独立操作，不把猜测变成确认事实，不填任意状态 patch 或最终数值；已发生事件只经 resolution.events 交登记标签及本段原文依据。结构校验不等于模型因果判断已被证明。

程序校验失败时整份回应不接受、不提前显示。消息原文、合法事件、实际差额及回执由RoundStore唯一持久事务保存；点按只写辅助阅读进度，不推进资源或记忆。普通行动、移动、交付及纯道具都须消费当前已演播完的段落，旧格式与旧选项不能绕过。失败、超时、取消先终止租约并全额返还预扣，退款与任务状态同锁接受；原编号重试重新核验余额，已退款尝试的迟到结果拒绝。存档被外部修改时暂停退款并保留恢复凭据，不覆盖外部事实。

- use_recovery_item：仅系统纯使用路径，含code与item_id；程序查活跃库存与效果，不由模型猜恢复量。
- 系统商城与 AI 定制询货（`shop_inquiry`）：0 体力、非剧情回合路径；商城同时合并静态目录与 `save_state.json["shop"]["dynamic_catalog"]` 动态货架，并统一校验 `unlock_req`（如商业嗅觉/好感门槛）。玩家在商城发起询货后，Operit 桥接通过无状态 `Tools.Chat.call` 生成 1～3 件候选商品，经后端严格红线与价位/时效闸门校验后原子落盘，绝不触碰或重置主剧情会话上下文。

## 费用、事件与时间

日常态（`intimate.scene_active == false`）下 A/B/C 固定 5/10/15 体力，固定 A/B 选项回合严禁打任何 `C烈度_*` 标签；亲密进行态（`intimate.scene_active == true`）下段末 A/B/C 按亲密节奏三档展开（`A` 缓拍温存仍禁 `C烈度_*`、`B` 肢体加深/换区/动用情趣道具放行 `C烈度_轻度/中度`、`C` 强势压制放行全部 `C烈度_*`），且连续第 2 拍起体力折减为 `5/7/10`（参数单一来源见《互动运行配置.json》）。普通自定义先暂扣当前最高档（日常 15 / 亲密折减 10），`resolution.category` 只判 A/B/C 并写 basis，程序退还差额。混合意图按实际成立行为最高档，只收一次。高费用不授权升级或保证成功。恢复道具纯指令是明确例外：严格文本“使用恢复道具 ITEM-编号”，或界面选择同一ID；由系统执行器核验，无模型调用、不暂扣。混合对白、移动或其他行为仍为普通自定义。

纯道具仅使用图鉴活跃、真实持有、未过期且【系统效果】为host_stamina:正整数的库存；数量与时效以原存档为准。实际恢复取登记效果、最大体力20%的剩余额度及距满差额中最小值；当前最大100，所以两次完整整夜之间累计最多20点，跨零点与记忆回合不重置，安稳整夜完成才重置。无库存、无效效果、满体力或额度耗尽不消耗。不得默认发恢复剂或另建道具账本。

resolution包含category、basis、clock、events、memory、conditions、sleep、task、items，并可选含intel_used（玩家在正文明确亮牌动用持有一次性商业情报时）、director_echo（action回合维护活体世界线索、暗钟微调与媒介记录）与scene_state（action回合更新房间级 `privacy`/`sub_location`/`present_actors`、衣着完整度、身体痕迹与女主间 `inter_heroine` 暗流增量；房间级 `present_actors` 同步作为本幕 `known_by` 隔离依据，避免同栋楼门外角色泄密）。正式桥接传输中，task无任务、sleep.start无起点、免费SYSTEM的conditions及conditions.npc无对象时允许明确空字符串，兼容合法null；桥接只在整份JSON合法解析后按这些精确路径转换为内部null。任何字段都不能冒号后留空，不在残缺JSON中猜补值。有任务/起点/条件时仍用原合法对象。本次精确结构由packet.output_contract给出。clock含day（游戏相对第几天）、time（HH:MM）、basis，按剧情实际经过时间单调推进，首次从游戏第1天初始化；真实设备日期、字数、点击或语音长度不用于计时。events每项含group、target、tags、evidence；只用本次注册表原标签，evidence须引用本段实际正文（若正文含 `｛表层｜潜台词｝`，支持原串或表层子串核验），不引用选项或未来计划。host_events的target固定为“系统宿主”，不能用主角姓名代替系统对象；其他事件按真实场内登记姓名（`徐承邺` 仅可作 `死亡查岗_沉沦期` 的 `depravity_events` target，禁填 `shame_events`/`ds_events`/`affection_events`；`inspect_deployed` 远程查探回合允许对装置所在地 `remote_cast` 结算 `自慰_暗中纾解` / `私密自渎` / `意外撞破_私密自渎`；目标体力 ≤ 15 且无玩家括号强行授权时硬拦截 `C烈度_深度/重度`）。模型不口算分，不直接写最终面板。「首次」「深度操控_首次」「内射_首次核爆（同步派生羞耻/堕落/宿主首杀）」「同质化免疫_回合2/3」「小憩单日最多1次」「失眠不可叠加」「状态_空耗惩罚」「生理_危险期」与被动 Lv.2（C 烈度好感惩罚减半）/Lv.3（NPC 体力消耗翻倍）/Lv.4（防线支配深侵蚀与豁免）均由后端依据 `存档/save_state.json` 确定性派生与拦截。宿主体力旧日常/激烈基础消耗与固定三档去重，守护奖励由有效行动计数推导；其他成立的登记奖励、恢复与人物事件继续结算。免费启动、道具及强制休息不能附带额外奖励/任务/道具。

memory.fact仅交有后续因果价值的新增事实，最多160字符；无新增价值时用空字符串，不为每次A或每段回答填摘要。保留明确约定、未完成事项、关系/权力变化、新获知信息与不可逆结果；说明谁向谁陈述、是否核实，未来计划标明未执行。纯寒暄、餐具杯盏位置、递水微笑、未选择饮料/未触碰等短暂现场琐事不进长期记忆；只有实际边界被明确提出或改变才记录，不能罗列未发生清单。时间地点由程序/当前状态提供，fact不重复报时或抄面板；现场衔接取近期原文。

程序按记忆回合保留重要fact并去除原句重复；同回合摘要上限600字符。若新fact将使其超限、或旧条已超限，交可选memory.compact：据当前条完整源与本段事实生成不超过600字符的单行完整合并摘要（严禁带 `【回合号】` 前缀或换行，运行层同步做清洗防呆），取代当前条的长串追加；可去琐事和同义重复，必须保留仍有效的约定、待办、重要因果和知情边界，不得抹去重要事实或将计划写为完成。缺摘要或超预算整份拒绝并退款，程序不机械截断旧事实。无价值段不增事实，无重要事实的回合可不占L1槽。系统纯恢复道具已由库存/回执追踪，不为每次使用追加故事记忆，不触发模型压缩。

memory.transfers仅在合法转移需要且本幕有新事实写入时，据packet/settlement_spec提供的完整原文 `memory_transfer_sources.source_bodies` 交l1_to_l2_condensed/l2_to_l3_summary/l3_to_l4_summary；若 `memory.fact == ""` 则 `memory.transfers` 必须交 `{}`。单条分别最多240/600/900字符（含显式范围），保持3/10/10/无限的四层容量与原源范围，不把无价值日常逐条升级。预算参数单一来源为互动运行配置.memory，本段与正式输出按当前配置执行。

游戏时间跨00:00或全部费用差额、合法事件和恢复后的体力不足5时关闭当前记忆回合一次。初始化凌晨、刷新、同日凌晨继续不重复关闭；零点不强迫睡眠、不回血。最终1～4保留真实余额，进入resting，普通抉择关闭；不得因15暂扣到零误判力竭。模型可依实际成立的累倒正文提交sleep.kind=collapse，但不据此擅自把余额扣零。

强制休息在当前后果演播完后，经“继续休息”免费系统入口交SYSTEM过渡，不再收5/10/15。sleep含kind、start、evidence；none时start=null/evidence空串，interrupted不回血且仍休息，overnight须有正文休息与起止依据、连续至少6小时并跨夜或凌晨入睡至05:00～12:59。实际完整安稳一晚后，宿主体力恢复至上限100、重置道具额度，且为当夜未触发失眠的女主恢复 +40 体力（上限100）并清零 `insomnia_applied`；短休、累倒、回合关闭与跨零点本身不补满。睡眠跨零点归同一收束，不制造空回合；醒来后才开放普通行动。睡眠时间与行动时刻必须一致，初始化不能据无历史起点重复收束。

## 旧系统单位、确定性通道与 P2 存档边界

普通付费action（A/B/C或自定义判档）必须提供conditions对象，即使只作澄清、行动未执行或无NPC也不可空。对象恰含intensity、effective_progress、scene、npc、action_changed、stress_signals、breakout_triggered七字段；intensity与category一致，两个变化字段为按事实判断的布尔值；无NPC仅npc为空，stress_signals为0，breakout_triggered为数组。禁止progress/action_change/stress_count/breakout等别名。免费SYSTEM的conditions为空；以本次resolution_policy区分，不能因无接触或有handoff自行省略对象。沿原字段定义与阈值。BUFF、道具行动时效、微状态、守护和破局累计每有效行动一次，点按/失败/重试/启动/纯道具/休息不累计；不以记忆号驱动。监视标签按事实、每经过完整游戏小时警惕衰减2、每有效行动回宅判定一次；不得将掷骰结果当未经发生的目击。

任务只依据实际面板判定完成，生成仍限原属性白名单，不能为任务改变剧情。新档开局确定性挂载首环轻量委托；当当前任务为空或已完成且本次为付费action时，后台结算结合当前实时面板数值自动续接下一条合规任务。未领取的已完成任务奖励保留在 `tasks.pending_items` 队列中，续接新任务不会覆盖或清空旧待领奖励。task未发则null；items每项含entry和正文evidence，增发须已有兑换或任务待发资格。其余角色事件依登记原源，不借新协议扩大秘密披露资格。

正式首页提供以下零体力、零模型调用的确定性系统事务（均在当前段演播完成且无在途任务时可用，经RoundStore唯一原子事务落盘，不推进游戏时间、不覆盖当前A/B/C抉择）：
- **系统商城兑换**：依据权威商品目录 `txt文件/系统商城目录.json`（严格遵守禁产出修改状态持续时间道具的红线），核验宿主积分余额与单档限购后扣分，并将道具实体（含来源、消耗积分、时刻备注与 `giftable` 标记）原子写入 `存档/save_state.json` 并单向渲染至 `存档/徐志北道具图鉴.txt`；
- **委托奖励一键领取**：当 `tasks.pending_items` 队列存在待领奖励时，玩家可在行囊页逐项领取入库并弹出队首，无需依赖正文凑写依据；
- **被动技能定向升级**：依据 `txt文件/互动运行配置.json` 的 `passive.costs` 扣除宿主经验值，针对单一女主将面板被动等级由 Lv.0 逐级升至 Lv.4；
- **商业情报整理与商业杠杆**：依据 `txt文件/商业情报目录.json` 校验商业嗅觉与接触条件后将一次性情报整理入库；嗅觉 ≥ 60 时可开启/关闭商业杠杆预备（待下一 C 烈度行动自动消耗并减半好感惩罚，可与被动 Lv.2 独立叠加）。

上述全部状态、确定性机制计数（`mechanics`）、四层结构化记忆与滚动最近 12 幕演播统一持久化于 `存档/` 内的三份 JSON 权威文件（`存档/save_state.json`、`存档/四层记忆.json`、`存档/近期演播.json`），并原子单向渲染 `存档/全局记忆库.txt` 与 `存档/徐志北道具图鉴.txt`；即便换设备/删除 `.round-runtime/` 或 `data.json`，重启服务仍可无损恢复近期演播、时钟、面板与记忆，新开对话窗口、切场景或重启服务后均不丢失记忆与限购状态。

## 在场、记忆与知情

人物当前位置取正式记忆库，由程序解析到scenario；静态人物卡不覆盖动态位置。提及人物资料只供背景判断，不使该人物在场。人物档案私有动机、秘密与信念不自动成为其他人的知识；称谓与资格取对应方向关系原文。遗嘱等秘密沿原资格锁，未定义披露规则不自动解锁。

player_private_state中的面板、库存、任务、商城记录与旧记忆只约束玩家连续性，不默认成为NPC共同记忆、话题或台词。为防止模型围绕未完成任务强行编排剧情，双阶段模式下 `进行中` 的任务目标对前台演播主模型物理隐藏，仅由前端界面展示、后台结算与引擎负责达标判定与续接；仅在委托刚刚达成、刚领取委托奖励或刚在商城兑换道具的特定时刻，由程序经一次性 `milestone_echo` 向下一付费行动前台注入低侵入微提示（允许在自然间隙用 1 句氛围、感官或内心轻顿带过，严禁直呼任务/委托/系统/商城/积分词，严禁扭转玩家意图或泄露给 NPC），成功落盘后自动消费清空。accepted_history按实际听众提供已接受原文；input_known_by与messages_known_by分别约束玩家输入和角色回应，移动前后的听众不能混同。引用历史陈述时保留是谁说的、是否核实；玩家怀疑亏损由某人造成不等于已确认责任。未履行的承诺不写为已完成。

正式packet按互动运行配置.memory选择完整记忆条目，总计最多6000字符，优先当前L1与玩家输入相关旧事实；不切半句，不把未选入视图当事实消失。即时状态仅带一次，不在accounting重复全部四层。近期原文最多6段且合计12000字符，完整段超预算则留在原归档；此时须据索引补读所需最近上下文，不能凭预算省略而猜造衔接。历史界面分页保持原规则，不因模型窗口缩小丢记录。

旧记忆索引最多24条，提供源路径和精确行号；合并或转移必需但未选入视图的原文在memory_transfer_sources.required_reads列出，由程序按本任务required_sources正文交付，或由模型通过真实文件工具补全；服务端核验相应源指纹、精确范围和正文覆盖。原记忆源只允许read_file_part按指定行号补读，禁止每段又整库重读。正式归档索引保存在本任务缓存，默认仅列24条路径，需要更早原文时先读index再补读允许路径，逐条核对实际听众。索引与指纹不能冒充正文；必要旧源补读可能超出自动视图预算，该预算不声称限制全部模型上下文。

正式会话默认持续沿用，不按资料包大小自动换窗；玩家可选择重启Python服务后新建、每个新行动新建，或空闲时手动重建。重试与提交前补读沿用当前会话；换存档、工作区或模型须安全隔离。重建保留旧聊天；每次任务携当前正式记忆、已接受剧情、原行动及上次错误，失败草稿不作为事实。程序直送及工具读取都必须由当前任务和租约新建审计，禁止复用旧交付记录。提交前若缺正文，只按程序给出的缺失范围在同一任务补读一次并重评完整回复；仍缺则停止并退款，不额外发起新行动。窗口或会话重建不会删除存档、增加阶段、扣资源或要求玩家另建实验场景。没有足够依据则澄清或返回待处理，不编造调查结果、共同经历或秘密。
