## 1. 正式互动资源与推进模型（`story_progression.py`）

当 `txt文件/互动运行配置.json` 启用 `resource.scheme == "fixed_tiers"`（当前版本 `version: 2`，状态 `active`）时，正式互动启用 schema v3 确定性推进与资源账本。

### 1.1 双轨三档体力（日常 vs 亲密双池保底）、托管预扣与差额退款

| 入口类型 | `option_id` | `kind` | 日常预扣 / 亲密续演预扣（`intimate_beat >= 1`） | 结算分类规则 | 差额退还 |
|---|---|---|---|---|---|
| 固定日常/余韵安抚选项 | `A` | `action` | **5** / **1**（触发保底时 **0**） | `resolution.category` 原样返回 `A`（日常严禁 `C烈度_*`） | 0 |
| 固定社交/升温慢烧选项 | `B` | `action` | **10** / **2**（触发保底时 **0**） | `resolution.category` 原样返回 `B`；亲密续演（`intimate_beat >= 1`）放行 `C烈度_轻度/中度` | 0 |
| 固定主动/深入主导选项 | `C` | `action` | **15** / **3**（触发保底时 **0**） | `resolution.category` 原样返回 `C` | 0 |
| 自由自定义输入 | `CUSTOM` | `action` | **15** / **3**（按 `active_costs(save_state)` 动态取 `C` 档） | 仅可判 `A / B / C`（不可免费 `SYSTEM`），按最高实际成立行动档位 | 按当前模式 `reserve - cost(cat)` 退差 |
| 纯恢复道具指令 | `CUSTOM` + 匹配 `PURE_ITEM` | `item` | **0** | `SYSTEM`，**本地同步执行，不走 LLM**（同步补 `+15/+25` 精力 `vigor`） | 0 |
| 强制休息过渡 | `REST` | `rest` | **0** | `SYSTEM`，须实际推进时间且 `sleep.kind ∈ {interrupted, overnight}` | 0 |
| 无段启动过渡 | `BEGIN` | `begin` | **0** | `SYSTEM`，禁止结算睡眠 | 0 |

- **托管预扣与亲密底线护盾（[`reserve()`](../../story_progression.py#L189) / [`refund()`](../../story_progression.py#L200) / `stamina_guard_info()` / `apply_stamina_floor()`）**：
  - 提交行动时经 `active_costs(save_state)` 依据 `save_state['intimate']['intimate_beat'] >= 1` 判定日常（`5/10/15`）或亲密续演（**`1/2/3`**）费用；当亲密场进行中且主角精力池 `intimate.host_phys.vigor >= 15` 时激活底线护盾：日常体力下限锁定在 **`10`（`intimate_stamina_floor`）**，当前体力 `<= 10` 时本拍日常体力预扣降为 `0`（改由独立精力池承担 `A:2 / B:4 / C:7 / release:12`），彻底杜绝亲密中段强制 `resting`。
  - 预扣时先把 `系统宿主` 体力扣减至 `after = before - total`，保存扣前 `存档/全局记忆库.txt` 的 Base64 原文、`original_revision` 与 `held_revision`，与 `tasks.json` 同锁原子提交；若任务失败、取消、租约超时或服务重启时仍处于 `preparing`，`refund()` 核对磁盘指纹等于 `held_revision` 后恢复扣前原文并核验等于 `original_revision`；若外部工具中途改过存档，则置为 `refund_pending` 并抛 `RecoveryError`，绝不盲目覆盖外部修改。
- **生理性断电硬锁（`体力 <= 15`）与远程监视事件（`inspect_deployed`）**：
  - 当在场目标女主 NPC `体力 <= 15` 时，引擎激活「生理性断电」防越权硬锁：若本轮产生深/重度侵入且玩家自由输入（`body.input` / `body.action`）未明确写出强势压迫括号授权（如 `（强势压迫授权）`），在 `resolution()` 校验期拦截越界升级，强制走余韵安抚或明确授权分支。
  - 执行 `inspect_deployed` 远程查看已部署隐蔽装置时，允许对远端房间目标结算 `ds_events` / `vigilance_events` 与观察态势，并严格禁止远端角色隔空发言或瞬移入场。
- **去重旧体力标签（[`resolution()`](../../story_progression.py#L303-L306)）**：
  - 正式互动会自动过滤模型上报的 `HOST_13`（-5）、`HOST_14`（-15）、`HOST_15`（=100）、`HOST_07`（守护奖励改由程序推导），避免与固定三档及整夜睡眠重复扣/加体力；若上报 `HOST_15` 但 `sleep.kind != 'overnight'` 则直接拒收。

### 1.2 游戏时钟、星期与场外作息流动、低体力与整夜睡眠判定

- **单调游戏时钟与星期推导（`minute()` / [`derive_weekday()`](../../story_progression.py#L332)）**：
  - `clock = {"day": int >= 1, "time": "HH:MM"}`，换算分钟数 `(day - 1) * 1440 + hour * 60 + minute`。
  - 首次初始化必须 `day == 1`（除非 `kind == 'rest'`）；后续推进必须 `end >= start` 且单步跨度 `<= 7 * 1440`（最多 7 天）。
  - `derive_weekday(data, memory_text, clock)` 基于序幕起始星期（`prologue.weekday` 或记忆首条推导）加上 `clock.day - 1` 确定性推算当前 `周一~周日`。
  - 每次推进计算跨过的完整游戏小时数：`hours = minute(new_clock) // 60 - minute(old_clock) // 60`（以完整小时为步长驱动监视警惕自然衰减）。
- **场外 NPC 确定性作息流动（[`reconcile_offstage_presence()`](../../story_progression.py#L696)）**：
  - 严格依据 `lore.驻地` 规则，**仅对与主角不在同一地点的场外 NPC**（`loc != player_location`）自动校准日程位置与事由（绝不瞬移同场人物；且非移动/非跨夜同室连续对话中绝不将场外人物静默塞入 `player_location`，兼顾叙事连续性与 `Zone 1` KV 缓存）：
    - `沈知韫`：工作日 `08:00–15:59` 在 `公司`，其余时段在 `徐家主宅`；
    - `徐念薇`：工作日 `08:00–16:59` 在 `大学`、`17:00–21:59` 在校外画室 **`工作室`**，`22:00` 后及周末回 `徐家主宅`；
    - `苏婉青`：常住 `市中心顶层公寓`；在主宅探访窗口（周二/周五 `15:30–18:30` 抵达请安、最晚 `20:30` 离宅；周日 `10:00–15:00` 家庭午餐窗）按时段往返，若事由含 `留住/过夜/宿/留下` 则尊重留宿安排，否则窗口结束后或跨日/整夜时若其处于场外自动返回 `市中心顶层公寓`。
  - 变动结果写入 `存档/全局记忆库.txt` 与结算回执 `schedule_moves`。
- **整夜安稳睡眠硬规则与声学标签兼容证据校验（[`_evidence_matches()`](../../story_progression.py#L67) / `resolution()`）**：
  - `_evidence_matches(evidence, texts)` 在比对 `sleep.evidence` 时自动剥离 Fish 英文/中文声学标签、Drama 3 XML 标签与音素标注并归一化空白差异（同时拒绝纯空白字符串），避免前台附带声学导演标记导致误拒收。
  - `sleep.kind == 'overnight'` 必须同时满足：
    1. `sleep.evidence` 匹配本段 `messages` 原文（非空白 ≤500 字）；
    2. `begun = minute(sleep.start)` 不早于本步开始时刻且 `begun < end`；
    3. 连续时长 `end - begun >= 360`（至少 6 小时）；
    4. 跨夜或凌晨入睡：禁止同日 `>= 06:00` 入睡（`not (begun // 1440 >= end // 1440 and start_hour >= 6)`）；
    5. 醒来时间在 `05:00 ~ 12:59`（`5 <= wake_hour <= 12`）。
  - 满足后将宿主 `体力` 恢复至 **100**，并将 `runtime.item_recovered` 重置为 **0**。
- **记忆回合关闭与强制休息状态机（`apply_staged()`）**：
  - `low = (final_stamina < 5) or (sleep.kind == 'collapse')`
  - `crossed = (old_clock is not None) and (new_clock['day'] > old_clock['day'])`
  - 当 `not was_resting` 且（`crossed` 或 `low` 或 `kind == 'rest'`）：关闭当前记忆回合（`last_closed = memory_round; memory_round += 1; closed_by = request_id`）。
  - 若 `kind == 'rest'` 或 `low`：仅在 `sleep.kind == 'overnight' and final >= 5` 时回到 `phase = 'ready'`，否则维持 `phase = 'resting'`（暂停一切普通行动与恢复道具，仅允许免费 `REST` 继续过渡）。
  - 处于 `was_resting` 期间若休息被打断（`interrupted`），事实仍归入 `last_closed`，不制造空记忆回合。

### 1.3 纯恢复道具与 20% 周期额度（`item_quote()`）

- **唯一触发格式**：`CUSTOM` 选项且输入严格匹配正则 `^\s*使用恢复道具\s*[：:]?\s*(ITEM-\d+)\s*[。！!]?\s*$`（或通过界面「使用恢复」按钮提交同 ID 的 `use_recovery_item`）。
- **校验条件**：图鉴活跃区存在该 ID、`当前状态 == '仓库中'`、`使用对象 ∈ {'', '无', '未使用', '徐志北'}`、`数量 >= 1`、`剩余时效` 非 0、临时道具有效倒计时 `>= 1`、且 `【系统效果】` 严格匹配 `host_stamina:([1-9]\d{0,3})`。
- **实际恢复量**：
  $$\text{gain} = \min(\text{effect},\; 20 - \text{item\_recovered},\; 100 - \text{stamina})$$
  - 若 $\text{gain} \le 0$ 报错且不消耗道具。
  - 两次完整安稳整夜之间累计恢复上限固定为 **20 点**（最大体力 100 的 20%）；跨零点或记忆回合关闭**不重置**该额度，仅完成 `overnight` 睡眠后归零。
- **同步零 LLM 执行（`create()`）**：由程序本地拼装一条旁白、保持原 `decision` 不变、不推进游戏时钟、不写 L1 故事记忆，直接进入 `validating` 并经 `RoundStore` 原子落盘。

### 1.4 记忆预算与 `memory.compact` 合并机制

参数唯一来源为 `txt文件/互动运行配置.json` → `memory`：

| 参数键 | 默认值 | 用途 |
|---|---|---|
| `fact_chars` | `160` | 单次行动新增 `memory.fact` 字符上限（允许空串 `""`） |
| `round_chars` | `600` | 同记忆回合 L1 累积摘要上限 |
| `l2_chars` / `l3_chars` / `l4_chars` | `240 / 600 / 900` | L1→L2 / L2→L3 / L3→L4 转移摘要上限 |
| `context_chars` | `6000` | 单次自动视图选入的记忆总字符预算 |
| `history_turns` / `history_chars` | `6 / 12000` | 自动视图携带的近期对话段数与总字符预算 |
| `index_entries` | `24` | 供按需补读的旧记忆/旧历史索引条数 |

- **`memory_merge()`**：
  - 自动去重：若去空白后的 `fact` 已是当前 L1 子串则忽略。
  - 若 `compact` 非空（要求原条 `prior` 非空），直接以 `compact` 取代旧条（≤600 字）。
  - 否则追加 `第{day}天 {time} {fact}`；**若合并后超 600 字绝不静默截断，直接抛 `RoundError` 并退款**，要求模型根据完整源提交 `memory.compact`。

### 1.5 活体世界导演 2.1（Living World Director v2.1 · 双轨解耦与硬保底）

由 [`story_progression.py`](../../story_progression.py#L79-L1940) 与统一数据源 `txt文件/世界变故库.json`（v2.1：8 类媒介枚举 + 25×25 常规火花矩阵 + **专属情欲火花矩阵 `sensual_spark_matrix`** + 4 条双阶段角色暗钟 + **75 条**精选支点事件，含 12 条 `sensual_hook`、**31 条四阶 `erotic_accident`（含 14 条 `requires_door_catch: false` 同室突发破冰/升温意外）** + 1 条 `covert_risk`）构成，参数唯一源为 `txt文件/互动运行配置.json` → `director`（内置 `pacing_presets`: `slow` 6 轮 / `standard` 4 轮 / `frequent` 3 轮）：

- **双轨解耦与确定性硬保底（`roll_director_beat(..., pacing_mode)`）**：使用 `secrets.SystemRandom()` 掷骰，将「女主契机轨」与「常规世界线轨」的冷却彻底分离：
  1. **女主契机独立轨（不受常规 `global_cooldown` / `soft_cooldown_penalty` 压制）**：当场存在女主且 `intimate.scene_active == false`、独立冷却 `heroine_cd <= 0` 时，按旱期 `sensual_drought` 走独立递增概率曲线（乘以节奏档 `heroine_prob_mult`）；一旦 `sensual_drought >= heroine_pity_turns`（默认 4 轮，即第 5 轮）触发 **100% 确定性硬保底**（`pity_triggered: true`，优先实质意外 `erotic_accident`），命中后置 `heroine_cd`（默认 `1`）与 `__EROTIC_CATEGORY__`（默认 `2`）并清零 `sensual_drought`，绝不连坐冻结常规世界线。
  2. **常规世界线轨（Entropy RNG + 三轨显著性）**：仅在女主轨未触发时执行：
     $$P_{\text{turn}} = \operatorname{clamp}\!\big(P_{\text{base}} + \Delta P_{\text{stagnation}} + \Delta P_{\text{tension}} + \Delta P_{\text{context}} + \Delta P_{\text{seed}} + \Delta P_{\text{clock}} - \Delta P_{\text{cooldown}},\; 0,\; P_{\max}\big)$$
     - `base_prob = 0.08`、`max_prob = 0.85`、`stagnation_curve = [0.0, 0.07, 0.16, 0.28, 0.44, 0.62]`（`calm_streak` 仅在真实进展/事件/换地点或触发变故时清零，不再被 `len(memory_fact) >= 24` 误清零）、真实张力因子封顶 `+0.35`、交界/深夜时段 `+0.10`、成熟伏笔 `+0.12`、就绪场外暗钟（`4/4` `+0.10`、`3/4` `+0.06`）；常规 `global_cooldown > 0` 压为 `0`，软冷却减 `0.25`。
     - 命中后按基准权 `thread_spark:45 / offstage_clock:30 / preset_beat:25` 路由至常规活体线索火花（旱期 ≥ 2 自动切入 `sensual_spark_matrix` 并标记 `sub_mode: "heroine_spark"`）、4 条离场角色暗钟（`CLK_XCY`/`CLK_SZY`/`CLK_XNW`/`CLK_SWQ`）或常规精选支点/伏笔链/隐蔽装置风控。
- **切入点显形契约（`format_surprise_directive()`）与幂等落盘（`advance_director_state()`）**：
  - 命中 `erotic_accident` / `sensual_hook` / `heroine_spark` 时自动附带 `choice_hook_guide`，要求前台在需要主角立刻伸手或表态的临界半拍定格，并让段末 `PROMPT` 与 `B（合法近身协助解围）` / `C（借势压近试探）` 直接锚定本次意外；
  - `packet()` 按 `request_id` 冻结进 `.context.json`；Stage 2 `SUMMARY` 可选返回 `resolution.director_echo`，经白名单净化后原子更新 `active_threads`、离场暗钟、双轨冷却（`global_cooldown` / `heroine_cd` / `event_cooldowns`）与 `recent_channels` 并写回 `save_state.json["director"]` 与 `【世界导演状态】`。

## 2. 登记操作与 `travel_intent` 地点解析（`interaction_runtime.py`）

正式互动支持 8 类登记操作（`txt文件/互动运行配置.json` → `operations`）：

1. **`move_player`** (`{code: "move_player", destination}`):
   - 合法地点 5 处：`徐家主宅`、`市中心顶层公寓`、`大学`、`工作室`（徐念薇校外私人画室）、`公司`。
   - 地点别名（唯一登记在 `location_aliases`）：`家 / 家里 / 家中 / 主宅 / 徐家 → 徐家主宅`；`公寓 → 市中心顶层公寓`；`画室 / 校外画室 / 念薇画室 → 工作室`。
   - **显式选项转场（方案 2B）**：段末 `A/B/C` 选项可直接通过 `[MOVE:登记地点]` 绑定 `operation: {"code": "move_player", "destination": ...}`，经 `selection()` / `validate()` 防篡改核验并由前端选项按钮一键触发。
   - **安全自由文本意图正则（`travel_intent()`）**：支持直接当下出发句式与简短自然物理过渡前导词（如 `起身告辞，去公司`、`喝完茶回主宅`、`告别出门，去画室看看`），同时严格拒收否定/将来/条件/疑问/二选一/多目的地及粘连词尾。
   - **只移动 `徐志北` 本人**（写入 `事由：玩家明确前往`），绝不自动搬运其他 NPC；换地点自动重置 `intimate` 态势（保留 `host_phys` / `body_dev` / `keepsakes` 持久化数据，仅冷却欲火 `-15` 并清零当前会话拍数）。
2. **`transfer_item`** (`{code: "transfer_item", item_id, recipient, quantity?}`):
   - 将仓库中由主角持有、未交付的 `ITEM-NNN`（支持部分数量 `quantity` 或整组）交给当前同地真实在场人物（`recipient ∈ scene_cast(presence, mem_text, player_place)`，支持在场的 `徐承邺`）；整组交付后置 `当前状态=已交付`、`使用对象=recipient`、`位置=当前地点`，防止重复交付。
   - 若通过自由文本隐式触发（`explicit=False`），必须同时包含接收人、交付动词（`交给|送给|递给|赠给`）、道具原名及整组限定词（`整组|全部|所有`）。
3. **`use_recovery_item`** (`{code: "use_recovery_item", item_id}`): 见 §1.3（同步恢复 `+15/+25` 主角精力 `vigor`）。
4. **`use_item`** (`{code: "use_item", item_id, target?}`): 主动使用消耗品（当回合起预挂 `turns + 1` BUFF）或反复可用工具（如 `SHOP-013` 丝绸眼罩与领带，使用后挂感官加成 BUFF 且不销毁工具本身）。
5. **`deploy_item` / `retrieve_item` / `inspect_deployed`**: 在当前地点隐蔽布防相机/拾音器/香薰装置（落盘至 `items.deployed` 并维护 `detected_risk` 暴露风险与计时衰减）、同地回收、或异地远程查看（自动透出 `remote_cast` / `remote_vitals_targets` 并允许远端结算 `ds_events`/`vigilance_events`）。
6. **`keepsake_action`** (`{code: "keepsake_action", keepsake_id, mode}`): 对私密珍藏盒（`intimate.keepsakes`）内 `KS-XXX` 执行 4 类动作——`sniff_play`（独处嗅闻把玩，`+18` 主角欲火）、`confront`（当面亮出对峙，要求物主同场并置 `owner_aware=True`；若物主高羞耻 `>=75` 且低堕落 `<15` 则反噬 `-1` 魅力）、`use_intimate`（亲密助兴，要求物主同场并将 `faded → stained_damp`）、`return_secret`（悄然归还并从珍藏盒移除）。

## 4. `injection_core.py` 确定性数值与状态系统全景

> **运行链路差异**：

以下全部 9 大系统及跨回合确定性机制的公式与阈值均经 `injection_core.py`、`save_store.py` 与 `txt文件/事件注册表.json`（6 组 **85 个**事件 ID）核实：

### 4.1 宿主积分/经验/嗅觉三轨竞价与 `HOST_16`（`process_host_system`）
