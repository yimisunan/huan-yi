## 3. 常见二次开发实操清单（Checklist）

### 3.1 新增或调整事件标签
1. 在 `txt文件/事件注册表.json` 对应组新增条目（合法 `id`、`tag`、`parameters`、`parameter_usage`、`description`、`pattern`、`shared_parameters`）。
2. 若涉及计算逻辑，在 `injection_core.py` 中一律通过 `_event_tag('ID')` 与 `_event_param('ID', 'param')` 引用（禁止硬编码标签中文名或魔法数字，否则 `round_runtime._engine()` AST 门禁报错）。
3. 同步更新 `txt文件/一键注入指南.txt` 与 `txt文件/知识库/系统标签类.json` 中的 `【注册表生成表】`，并重建 `Operit世界书导出/`。
4. 跑 `test_story_compiler.py`、`test_save_architecture_v2.py`、`test_adult_systems_v3.py` 与 `回合执行验收.py` 验证同步无误。

### 3.2 新增地点或地点别名
1. **仅改一处配置**：在 `txt文件/互动运行配置.json` 更新 `locations` 或 `location_aliases`。
2. 如新增地点，补充前端 [`story_client.js`](../../story_client.js) 中 `MAP_COORDS`（坐标）与 `renderSceneVector()`（建筑 SVG 线稿），在 `txt文件/image/scenes/` 放入 `<地点名>_{day,night}.webp`（或 `.png`/`.jpg`）空镜图，并在 `txt文件/知识库/世界观类.json` 补齐驻地描述。
3. 跑 `test_live_action_contract.py` 与 `test_visual_runtime.py` 验证别名与空镜自动发现。

### 3.3 新增主要角色
1. `txt文件/关系称谓库.json` 添加实体/事实/角色/称谓（含 `intimate` 场合）→ 运行 `relationship_query.py render > txt文件/关系称谓查询.jsonl` 并 `check`。
2. `txt文件/知识库/角色类.json` 新增带 `※索引key※ char.<姓名>` 的完整人设条目 → 运行 `convert_to_operit.py`。
3. 同步更新代码常量：`save_store.py` 面板/所在/女主默认表、`story_compiler.PEOPLE`、`interaction_runtime.PEOPLE`、`round_runtime.ROUND_NPCS`、`injection_core.DEFAULT_PRESENCE`（及必要时的 `VIGILANCE_TARGETS`）、`story_client.js` `PEOPLE`/`CHAR_META`、`story_client.css` `[data-speaker="..."]`、`voice_config.json` 音色配置与 `txt文件/image/<姓名>/` 立绘。

### 3.4 新增桥接可配开关（全链路双端同步）
1. **核对 Operit 2 宿主 API**：改动涉及 `ToolPkg`、`ComposeDslScreen`、`Tools.SoftwareSettings.exec` 或 `com.operit.character_cards` 时，先查阅 [`06_Operit2桥接插件架构.md`](06_Operit2桥接插件架构.md) §1、本地 [`scene_chat_dev/types/`](../../scene_chat_dev/types/) 与 [Operit 2 官方在线知识库](https://luojiaping.github.io/Operit2-wiki)（Operit 2 处于 Preview 阶段，以目标版本真实源码与 SDK 声明为准）。
2. **后端 (`story_service.py`)**：在 `bridge_control()` 注册新 `action` 与参数校验（按需加空闲锁），在 `worker_control()` 的 `runtime` 上报和 `_bridge_view()` 透传字段。
3. **桥接插件 (`main.js` + `tools.js` + `ui/settings.ui.js`)**：在 `settings()` 加默认值 → 在 `receive()` 处理该 `action` 并在成功后调用 `void monitor()` → 在 `runtimeReport()` 填报 → 在 `ui/settings.ui.js` 加控件（异步回调注意结合 `useRef`）→ 如有必要在 `tools.js` 补 `configure` 参数。
4. **前端 (`main_template.html` + `story_client.js`)**：在 `#connectionDialog` 添加控件、绑定 `sendBridgeControl()`、在桥接状态渲染函数同步状态。
5. 递增 `manifest.json` / `main.js` `PLUGIN_VERSION`、`ui/settings.ui.js` 回退版本与 `.gitignore` 白名单 → 跑 `bridge_*.js` 全部 9 组 → `python3 scene_chat_dev/build.py` 打包（自动清理旧包）并在 Operit 2 同 ID 覆盖导入。

| 所有 `/api/story/*` 返回 `存在未完成清理` (`RecoveryError`) | 上次新档重置中途断电/杀进程，残留 `.round-runtime/reset-journal.json` | 停服务 → 运行 `python3 存档清理器.py --recover`（自动完成回滚或提交）→ 重启服务 |
| 提交报 `未完成事务尚未恢复` (`RecoveryError`) | `.round-runtime/journal.json` 损坏或文件权限异常 | 检查磁盘空间与权限 → 运行 `python3 round_runtime.py recover`（只按 WAL 重放，严禁手删 `journal.json`） |
| 报错 `存档被外部改动，退款待恢复` (`refund_pending`) | 预扣体力的任务在途期间，有外部程序直接修改了 `存档/*` 或 `data.json` | 核对 `.round-runtime/story/tasks.json` 中的 `reservation` 扣前快照与当前存档差异；若需强行脱困可对滞留任务调用 `/cancel` 清除阻塞，或在桥接空闲时通过 `/api/story/new-game` 重新开档 |
| 行动卡在「已入列 · 等待领取」 | Operit 2 被后台冻结、桥接未启动或插件版本 `< 2.1.9` | 保持 Operit 2 前台/小窗可见，导入 `scene_chat_dev/artifacts/故事桥接-continuous-2.1.9.toolpkg` 并重启服务 |
| 双阶段流式出现 `旁白：[N]` 粘入对白框、网页提示有新版待导入或外部删窗后缺历史 | Operit 中安装的插件版本低于仓库最新版（`< 2.1.9`） | 在 Operit 2 中同 ID 覆盖导入 `scene_chat_dev/artifacts/故事桥接-continuous-2.1.9.toolpkg`，确认 `story_compiler.py` 已更新（`zone0_sha256` 变更会自动刷新角色卡） |
| 后台结算连续失败但前台剧情正常 | `SUMMARY` 槽绑定了过弱/不支持 JSON 的模型，或误设思考导致超时 / 关思考导致无法纠偏 | 在设置页将副模型结算思考模式保持为 `auto`（智能自适应，推荐：首跑极速、校验失败自动提权开启思考纠偏）或 `off`（极速）；若副模型完全不支持思考能力导致报错，可绑定 Gemini 2.5 Flash 或 DeepSeek-V3 并确认模式为 `auto` |
| 升级 Operit 2 新版后插件报错（依赖/角色卡/设置页/工作区绑定失败 `workspace does not exist`） | Operit 2 Preview 阶段宿主 API、Core Command（如 `workspace bind` 改为只认工作区 UUID）或 `com.operit.character_cards` 契约变化 | 升级覆盖导入 `故事桥接-continuous-2.1.9.toolpkg`（内置 `workspace list` / `resolve-path` / `create` 自动匹配与设置页一键选择已有工作区）；若遇其他上游变更，对照 [Operit 2 仓库](https://github.com/AAswordman/Operit2) 与 [在线知识库](https://luojiaping.github.io/Operit2-wiki) 检查接口并重跑 9 组 `bridge_*.js` 重打包导入 |
| 安卓 Termux/Pydroid 游玩中途报 HTTP 500 或 `.round-runtime/lock` `FileNotFoundError` | 安卓 `/storage/emulated/0` FUSE 锁节点失效或系统清理 0 字节文件；需查看完整后端异常堆栈 | 升级至包含 `acquire_process_lock()` 的 `round_runtime.py` 后重启 `语音运行.py`（安卓 FUSE 路径已自动改用原生 `tmp` 锁文件并支持自动回退）；若仍遇 500 异常，直接在项目根目录可见文件夹查看 **`日志/story_error.log`** 获取完整时间戳堆栈 |

## 5. Git 交付与代码卫生纪律

遵循 [`.agent/rules/main-branch.md`](../../.agent/rules/main-branch.md) 与 [`AGENTS.md`](../../AGENTS.md) 边界：

1. **严禁 `git add .`**：必须显式逐文件暂存本次任务修改，杜绝把 `data.json`、`存档/*`、`voice_config.json`、`.nomedia` 现场差异或临时缓存带入提交。
2. **标准落地流**：功能分支提交并通过对应验证 → `git checkout main` → `git pull --ff-only` → `git merge --no-ff <branch>` → `git push origin main`（**严禁 `--force`**）。
3. **非数据源卫生**：所有新增的工程文档、测试夹具与维护记录均不得被引用为 AI 剧情运行时数据源；严禁在任何权威规则原源正文内打版本补丁标签。
