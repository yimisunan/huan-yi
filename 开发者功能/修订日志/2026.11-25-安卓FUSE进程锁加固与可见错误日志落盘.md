# 2026-11-25 安卓 FUSE 进程锁加固与可见错误日志落盘

> 范围：事务进程锁（`round_runtime.py`、`存档清理器.py`）、后端 500 可见日志（`story_service.py`）与 `.gitignore` 卫生同步。

## 1. 问题背景

1. 在 Termux / Pydroid 3 运行于安卓共享存储（`/storage/emulated/0/...`，经 Android MediaProvider FUSE 挂载）时，位于隐藏目录 `.round-runtime/` 内的 0 字节无后缀锁文件 `.round-runtime/lock` 易被系统清理或触发 FUSE dentry/inode 失效，导致 `RoundStore._locked()` 在调用 `open('a+b')` 时持续抛出 `FileNotFoundError (ENOENT)` 并返回 HTTP 500。
2. `/api/story/*` 的 500 兜底仅返回笼统提示且堆栈只输出在终端，未落盘到非隐藏可见日志文件，手机端用户无法按路径排查。

## 2. 核心改动

- **安卓 FUSE 安全进程锁（`round_runtime.py`、`存档清理器.py`）**：
  - 新增 `acquire_process_lock(root, timeout, conflict_message)`：对安卓共享存储路径（`/storage/emulated/`、`/sdcard/`、`/mnt/media_rw/`）优先将跨进程锁文件置于原生 ext4/f2fs 临时目录（`tempfile.gettempdir()/huan-yi-locks/<项目路径哈希>.lock`），普通 Linux/桌面路径保持 `.round-runtime/lock` 优先且互为备选。
  - 锁文件首次创建时写入非空标记 `1\n` 避免被 0 字节清理器误删；主锁路径遇 `ENOENT`/`ESTALE`/`EACCES`/`ENOTSUP` 等自动回退备选路径；遇文件系统不支持 `fcntl.lockf` 时自动降级依赖进程内 `RLock`，不再直接抛 500。
  - `RoundStore._locked()` 与 `存档清理器.py` 的 `reset_lock()` 统一复用 `acquire_process_lock()`，保持跨进程锁路径完全一致。
- **可见错误日志落盘（`story_service.py`）**：
  - `/api/story/*` 的 500 兜底新增 `_append_story_error_log()`，自动将带时间戳的完整异常堆栈追加写入项目根目录非隐藏文件夹 `日志/story_error.log`（超过 256 KB 自动保留尾部 128 KB），并在 JSON 错误消息中直接指明异常类名与日志路径。
- **卫生同步（`.gitignore`）**：将白名单条目更新为 `故事桥接-continuous-2.1.9.toolpkg`；清理临时诊断附件 `开发者功能/.round-runtime.zip`。

## 3. 验证

- 实测安卓 FUSE 锁路径优先级、主锁模拟 `FileNotFoundError` 自动回退、`fcntl.lockf` `ENOTSUP` 优雅降级、互斥 `ConflictError`、`RoundStore._locked()` 重入、`存档清理器.reset_lock()` 及 `story_service` 500 写入 `日志/story_error.log` 全部通过。
