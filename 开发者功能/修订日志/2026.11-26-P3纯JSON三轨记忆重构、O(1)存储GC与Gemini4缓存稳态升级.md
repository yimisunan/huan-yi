# 2026-11-26 · P3 纯 JSON 三轨记忆重构、O(1) 存储瘦身 GC 与 Gemini 4 缓存稳态升级

> 对应审计报告：记忆与存档系统全链路只读架构调研（方案 A + 选项 2-1 单向 `.txt` 视图 + 选项 3-1 编年史搭车 Stage 2 归档）。

---

## 1. 背景与根因

面向数百轮长局连续游玩与 Gemini 4 隐式前缀缓存（Implicit Prefix Caching）架构，旧版 P2 存档与运行时存储存在六类长期瓶颈：

1. **`tasks.json` 与 `journal.json` $O(N^2)$ 写放大**：已完成/退款任务从未清理 `reservation.before_memory` / `before_save_state` Base64 快照且无终态上限，长局 500 轮下单次提交触发数百 MB 级重复序列化。
2. **四层线性压缩失真与 `known_by` 死代码**：旧 `存档/四层记忆.json` 的 L1–L4 缺乏永久事实锚点与有效知情隔离，且旧 600 字同日重写陷阱容易引发整轮结算失败。
3. **无界目录与列表膨胀**：`txt文件/.story-reading/<hash32>/` 与 `.round-runtime/story/<hash64>.*` 永不 GC，`state.json.receipts`、`items.delivered` / `items.history` 无封顶，`interaction_runtime.packet()` 全量扫描所有历史归档文件。
4. **Gemini 4 隐式前缀缓存抖动**：`Zone 1` 中 `欲望 >= 30` 与 `警惕 > 0` 阈值过低，日常同幕微幅波动即击穿 `Zone 0 + Zone 1` 字节前缀缓存。
5. **双阶段载荷冗余**：`dual_stream_v2` Stage 1/2 仍残留 `required_sources` 死重，桥接 `main.js` 向 Stage 2 同时重复发送 `foreground_script` 与 `foreground_messages`。
6. **新人进房历史断层**：新角色加入同房间时，`history_audience` 交集收紧可能导致最新一幕房间内刚发生的上下文缺失。

## 2. 核心变更明细

### 2.1 三轨结构化记忆引擎与纯 JSON 真相（`save_store.py`）
- **新权威文件**：正式以 `存档/memory_store.json`（`MEMORY_STORE_PATH`，保留 `MEMORY_LAYERS_PATH` 别名兼容）取代旧 `存档/四层记忆.json`（`LEGACY_MEMORY_LAYERS_PATH`）。
- **三轨数据结构**：
  - **轨 1 `anchors`（永久事实锚点，上限 60 + `resolved_anchors` 40）**：存储重要约定、关系转折、线索、秘密与藏物，支持 `add` / `update` / `resolve` 原子维护，长局 500 轮永不因轮转丢失；内置 **K01 绝密硬守卫**（`_guard_k01_known_by`），未解锁时自动剥离越权知情者。
  - **轨 2 `episodes`（近期情景幕，热窗 24、硬上限 32）+ `pending_buffer`**：`record_memory_turn()` 在地点变化、在场知情者变化、跨日、过夜或缓冲满 4 条 / 360 字时确定性自动封箱，并打上后端权威房间级 `known_by`。
  - **轨 3 `chronicle`（分视角编年史，上限 16 章）**：当 `len(episodes) >= 24` 时由 `needs_chronicle_archive()` 自动唤醒低频搭车归档，将最旧 8 幕交由 Stage 2 折算为 `public` 公共纪要 + 分角色 `views` 私密线（零额外 LLM 调用）；超过 32 幕时启用确定性安全阀防失控。
- **四因子零依赖检索与编译期知情硬分区（`retrieve_memory_view()`）**：综合实体相关性（0.40）、词项/地点匹配（0.30）、重要度（0.20）与时间衰减（0.10）排序选文（默认预算 2400 字、单轮至多 8 幕 + 4 条编年史），并按在场 `room_actors` 与 `known_by` 确定性切分为 `shared_scene_memory`、`actor_private_memory` 与 `host_private_memory`。
- **单向 `.txt` 视图与零解析直读**：保留 `存档/全局记忆库.txt` 与 `存档/徐志北道具图鉴.txt` 供人工与手动入口只读查阅；`load_bundle()` 常态直读 JSON 且在 `rendered_sha256` 匹配时完全跳过 `.txt` 正则反解析，仅当遗留引擎沙盒改动 `.txt` 时通过窄边界 `harvest_engine_txt_mutations()` 收割面板/任务/道具/生命周期增量，绝不触碰 `memory_store.json` 或 JSON 原生子系统（`intimate`/`mechanics`/`npc_mind`/`runtime`/`dynamic_catalog`）。
- **道具列表封顶与近期演播扩容**：`items.delivered` 封顶 40、`items.history` 封顶 50，`MAX_RECENT_SEGMENTS` 提至 16。

### 2.2 运行时 $O(1)$ 存储瘦身与自动 GC
- **`story_progression.py`**：新增 `prune_tasks_state()`（在 `commit_tasks()`、`refund()` 与 `story_service._write()` 统一执行），清除所有非 `held` 任务的 `before_memory` / `before_save_state` Base64 快照并将终态任务裁剪至最近 20 条；`resolution()`、`contract()` 与 `apply_staged()` 全面切换至 v2 三轨记忆契约（`fact` 严格遵循配置 `fact_chars=160`、`anchor_ops` 最多 3 条、`chronicle_digest`），废弃旧 600 字同日重写报错与 `engine.update_global_memory()` 写入。
- **`round_runtime.py`**：`FILES` 切换为 `save_store.MEMORY_STORE_PATH`；`state.json.receipts` 封顶 `MAX_LEDGER_RECEIPTS = 120`；提交时剥离已结算任务预留快照；`_memory_state()` 直读 v2 `memory_store.json`。
- **`story_service.py`**：新增 `_gc_runtime_artifacts(state, keep_recent=3)` 并挂入 `_finish()`，每次提交自动清理超出最近 3 个请求的 `txt文件/.story-reading/<hash32>/` 与 `.round-runtime/story/<hash64>.*` 孤儿缓存。
- **`interaction_runtime.py`**：新增 `recent_rows_tail(limit=24)` 仅尾读最近 24 幕归档替代全目录反序列化；`settle()` 归档前剥离 `audit.reservation` 大快照；新增 `recent_room_continuity` 填补新人进房后的上幕房间内连贯性；`dual_stream_v2` 彻底取消 Stage 1/2 的冗余 `required_sources`。

### 2.3 Gemini 4 隐式前缀缓存锁与双阶段载荷去重
- **`story_compiler.py`**：`_needs_vigilance_rules()` 抬升至 `max_vigilance >= 20`，`_needs_intimate_zone1()` 抬升至持久高欲求 `>= 60`（日常 `欲望 0→50` 与轻度 `警惕 0→15` 波动期间 `Zone 0 + Zone 1` 字节级完全不变）；`build_user_delta()` 注入 `scoped_memory` 知情分区与 `continuity_hook` / `recent_room_continuity`；`build_settlement_spec()` 规则 6 升级为 v2 三轨契约、规则 13 兼容 `foreground_decision_missing` / `foreground_decision_tail`，精简至 **12,258 字**（`< 12,500`）。
- **`scene_chat_dev/local.story.operit_bridge/main.js`**：Stage 2 仅传结构化 `foreground_messages` + `foreground_decision_tail` + `foreground_decision_missing`（仅在预览为空时回退 `foreground_script`），消除双倍正文冗余；已通过 `build.py` 重打包 `scene_chat_dev/artifacts/故事桥接-continuous-2.2.0.toolpkg`。

### 2.4 外围工具适配与新档重置
- **`存档清理器.py`**：新增 `LEGACY_MEMORY_LAYERS = '存档/四层记忆.json'`，重开新档时自动清退旧文件并纳入恢复白名单。
- **`存档开局随机盲盒.py`**：开局直接调用 `save_store.default_memory_store()` 写入带精确房间级 `known_by`、地点、子区与时间的 v2 `存档/memory_store.json`。
- **`scene_world.py`**：兼容从 v2 `memory_store.json` 的 `episodes` 读取 `known_by`。
- **仓内新档重置**：已移除旧 `存档/四层记忆.json`，初始化干净 v2 `存档/memory_store.json`、`存档/save_state.json`、`存档/近期演播.json` 与单向 `.txt` 视图。
