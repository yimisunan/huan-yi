# 2026.11-27 · 主模型道具可见性全链路重构、自由文本补发与自定义非修改器红线

> 定位：主模型道具上下文编译、前后端道具操作闭环、Stage 2 自由文本道具推断与自定义商城防作弊护栏迭代归档。本文件为开发修订记录，严禁作为 AI 剧情运行时数据源注入。

---

## 1. 背景与根因

围绕「前台主模型在持有 / 已部署 / 已赠出 / 使用当轮 / 增量轮是否真正清楚道具作用、用法与边界」开展全链路只读审计，定位到六类真实缺口：
1. **首轮与增量轮割裂且出戏冗余**：`build_user_delta()` 首轮发送原始 19 键 `items`（含冗余 `fields` 与「系统商城兑换/积分」出戏词），增量轮却换为缩水版 `held_items` 且截断自定义 `DYN-*` 描述，导致主模型首轮过胖、后续轮丢失用途。
2. **已赠礼字段错配与清空漏发**：`ir.view()` 产出 `delivered_items[].target`，而 `story_compiler.py` 只读 `recipient` 导致 `delivered_gifts_to_cast` 长期静默为空；全部道具列表在「非空 → 清空」时未向增量 delta 显式发送 `[]`，模型误以为旧道具仍在场。
3. **已部署装置缺描述与风险提示、珍藏缺来源**：`deployed_items_here/remote` 仅发位置与名称，缺少 `desc`、自然语言化 `capability` 与高风险定性提示；`compile_state_qualitative_brief()` 未呈现珍藏获取方式与简短描述。
4. **增量轮长对话失忆与自由文本脱节**：背包未变时被 diff 省略，玩家在自由输入或普通选项中提及道具时主模型缺少当轮召回，且后台 Stage 2 无自由文本补发指引、`assemble()` 仅在存在 UI `command` 时写入 `requested_operation` 导致非 `CUSTOM` 选项被 `selection()` 误拦。
5. **前后端操作细节断层**：前端传 `target='室内氛围'` 触发 `ir.operation()` 400 白名单报错；`_describe_operation_context()` 漏写 `use_recovery_item` 专用说明且在 `use_item` 中裸露 `buff:` 与机制算式；`SHOP-014`（无色微醺桃露）描述与 `injection_core.py` 实际生效逻辑不齐。
6. **自定义商城「非修改器」边界过宽**：旧 `SHOP_FORBIDDEN_DYN_RE` 仅拦截极少数词条，未成体系拦住直接增减好感/羞耻/堕落/魅力/嗅觉/体力精力/积分经验/清警惕等属性修改器型定制道具。

## 2. 分批次核心改动（P0 + P1 + P2 全量落地）

### Batch 1：目录对齐与自定义商城「道具不是修改器」硬护栏
- **[`txt文件/系统商城目录.json`](../../txt文件/系统商城目录.json#L265)**：`SHOP-014` `system_effect` 统一收敛为 `buff:微醺燥热:3:脸颊潮红呼吸发烫，防备松动与越界缓和（轻中度越界好感惩罚减半）`，与 `injection_core.py` 实际计算完全一致。
- **[`story_progression.py`](../../story_progression.py#L46-L61)**：升级 [`SHOP_FORBIDDEN_DYN_RE`](../../story_progression.py#L50-L60) 与 [`validate_dynamic_shop_items()`](../../story_progression.py#L552-L581) 拒收提示，覆盖全部直接属性增减（数值 `±N`、直接增减/清零/拉满/回复动词、使用后即增减、属性药水/修改器命名），同时放行氛围、感官放大、话题破冰、防备松动与越界缓和、策略备忘、隐蔽监控等间接辅助道具。
- **[`story_client.js`](../../story_client.js#L6180)**：商城定制弹窗提示文案同步明确「题材自由，仅作间接辅助，非直接增减属性的数值修改器」。

### Batch 2：前后端道具操作闭环与 Stage 2 自由文本实证守卫
- **[`interaction_runtime.py`](../../interaction_runtime.py)**：
  - [`operation()`](../../interaction_runtime.py#L836-L977)：`use_item` 目标白名单纳入 `'室内氛围'`（与 `story_progression.py` 展开至在场全体女主逻辑对齐）；升级 `explicit=False` 下 `use_item` / `transfer_item` / `deploy_item` 为精确名称/唯一核心名词匹配，并为 `retrieve_item`、`inspect_deployed` 补齐文本实证门禁，防止后台幻觉补发。
  - [`_describe_operation_context()`](../../interaction_runtime.py#L1371-L1485)：补全 `use_recovery_item` 分支（含名称、描述、余量与不推进时间禁令）；`use_item` 与 `retrieve_item` 全面接入 `humanize_item_effect()` 去除 `buff:` 与机制术语，并标明永久工具保留 vs 消耗品余量。
  - [`assemble()`](../../interaction_runtime.py#L2792-L2850)：无条件记录 `accepted_audit['requested_operation'] = copy.deepcopy(context['command'])`（含 `None`），确保自由文本与普通选项由 Stage 2 补发道具操作时顺利通过 `selection()` 校验。

### Batch 3：主模型道具编译统一化、增量按需召回与 Stage 2 提示
- **[`story_compiler.py`](../../story_compiler.py)**：
  - 新增单一事实源辅助层：[`humanize_item_effect()`](../../story_compiler.py#L1606-L1627)、[`match_item_in_text()`](../../story_compiler.py#L1687-L1712)、[`find_mentioned_items()`](../../story_compiler.py#L1715-L1720) 与 [`_emit_diff_list()`](../../story_compiler.py#L1723-L1731)（由 `interaction_runtime.py` 复用，避免双源维护）。
  - [`build_user_delta()`](../../story_compiler.py#L1752-L2295)：
    - 首轮与增量轮统一输出自然语言化 `held_items`（`id / name / qty / use_way / desc[:160] / effect`），剔除冗余 `fields` 与商城积分出戏词；3 件常规背包首轮由 `1,584 → 495` 字（**-68.8%**），150 字定制描述零截断。
    - `deployed_items_here` / `deployed_items_remote` 补齐 `desc`、自然语言化 `capability` 与高风险定性提示 `risk`。
    - 修复 `delivered_gifts_to_cast` 兼容 `target` 与 `recipient` 并携带简短 `desc`；四类道具列表统一经 `_emit_diff_list()` 在「非空 → 清空」时显式输出 `[]`。
    - 增量轮新增按需 `mentioned_items` 精确召回（附「背包持有 / 已部署(当前现场) / 已部署(远程)」状态标识，多件重名核心词歧义时不盲猜）；定制轮 `shop_custom_directive.rule` 同步写入「道具不是修改器铁律」。
  - [`compile_state_qualitative_brief()`](../../story_compiler.py#L939-L1265)：去除 `char_buffs` 数值术语并补全私密珍藏获取方式与简短描述。
  - [`build_settlement_spec()`](../../story_compiler.py#L2448-L2615) 与 [`_build_free_text_item_hint()`](../../story_compiler.py#L2384-L2445)：仅当本轮无 UI 操作且玩家提及已有/已部署道具时动态注入 `user_context.free_text_item_hint`，定制轮动态注入 `user_context.shop_custom_rule`；保持 **Zone 0 / Zone 1 零漂移**（`Zone 0 = 8,959` 字），Stage 2 静态 `system_prompt = 11,989` 字（严格 `< 12,000` 预算）。
