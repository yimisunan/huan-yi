# 回合执行基础交付说明

用户在只读调研后授权实施。本次完成回合执行基础，保留现有Python入口；没有启动模型生成、真实注入或服务器。

## 已交付

- `round_runtime.py`：prepare/check/apply/recover命令及RoundStore Python接口。
- `injection_core.py`：公开入口统一接入固定执行器；V1失败声明拒绝；日志在隔离项目内生成；内部任务校验失败显式报错。
- `txt文件/一键注入指南.txt`：固定执行器的权威调用契约，事件标签仍维护于原总表。
- `开发者功能/开发者工具/回合执行验收.py`：合成存档的可重复验收，不使用真实剧情数据。
- `.operit/sync.json`：保留默认限额，排除运行事务目录、备份和验收临时目录。

运行时不需要新增第三方依赖。原前端及语音服务未修改。三个既有修改文件的原文已按同目录时间戳保留，详情见本目录`安装清单.json`。

## 使用

在项目目录运行：

```bash
python3 round_runtime.py prepare
python3 round_runtime.py check round_request.json
python3 round_runtime.py apply round_request.json
python3 round_runtime.py recover
```

`prepare`输出生成前的版本、下一回合、摘要来源及一致快照。调用端应保存该版本并生成一次请求号，然后让AI产出数据。不要在生成后重取版本来为过期剧情补签。

`check`仅在隔离目录试结算，`apply`才提交。`recover`处理上一次中断的事务。字段与返回值以`txt文件/一键注入指南.txt`为唯一契约，此处不复制第二套模板。

原Python脚本继续调用`execute_injection`，原参数位置保留。新脚本可传`request_id`与`base_revision`；未携带版本的旧脚本不能获得生成前状态的过期检查。非法格式现在会拒绝，而非默默吞字段。

`.round-runtime/state.json`是运行后自动生成的本地请求回执记录；不要手动清空它来解决冲突。若以后使用原项目清档工具开启新游戏，需要同时设计会话重置，避免旧请求回执跨存档使用。本次没有修改或运行清档工具。

## 边界及下一步

- V1声明格式检查不能证明AI已读取设定或剧情符合语义；设定装配和语义复核后续实现。
- 多个文件逐个替换，不宣称跨文件原子；中断后由持久记录恢复。旧网页直接取多个文件时仍可能跨版本，应在页面接入时使用一致快照接口。
- 已验证的是进程中断恢复，没有模拟物理断电；共享存储持久性受操作系统和文件系统限制。
- 本次测试宿主为Android proot Python3.14.5，共享存储目录。用户日常Pydroid3解释器、超过已知冻结窗口的长期运行尚未实测。
- 当前使用原模型、原网页时，操作步骤尚未减少；已提供消除手动脚本执行所需的固定入口，下一阶段应接页面任务与对应Operit版本的生成接口。
- 各公开入口用相同记录锁串行执行；存档维护工具不属于该锁协议，使用它们时应先停止生成/提交。
