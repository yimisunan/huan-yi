# 桥接启动与连接引导

代码与同ID插件已安装，插件版本1.2.0，处于暂停状态。33项定向隔离检查通过；真实插件的固定查询/暂停指令已执行成功。正式回合仍为0，原行动和存档未变。

## 现在怎么用

1. 在Pydroid3停止并重新运行现有的`语音运行.py`，让`story_service.py`的新接口加载；然后刷新故事网页。
2. 打开Operit并保持小窗可见。点故事页右下角行动入口，在“下一步行动”面板点“启动桥接”。页面会分别显示本地服务、桥接连接和回合进度。
3. 首次连接或页面仍等Operit时，在Operit输入框直接发送`/storybridge start`。固定指令由插件执行；`/storybridge status`查看状态，`/storybridge stop`暂停。完整短句“启动故事桥接”也有精确拦截；单独的“启动”仍是普通聊天输入。不要在“故事生成 · 项目工作区”专用聊天手动续写。
4. 原行动已保留，无需重复提交或清档。当前原任务确认的是`DeepSeek/deepseek-v4-flash`，桥接当前读取到的是`665535GPT/gpt-6.1-sol`。若继续用当前GPT，首次领取原任务会因模型不同而停止，随后在网页点“重试原行动”，核对模型并确认后继续。若要用DeepSeek，先由用户在Operit功能模型设置中选回所需模型；本轮未替用户修改模型。
5. 连接后可在页面启动/暂停；暂停不打断已领取回合。网页无法唤醒未运行或被厂商冻结的Operit，本机需保持可见小窗。

## 改了什么

故障起因是桥接保存的专用聊天已不存在，旧插件不断报`Chat does not exist`。现在启动前按自有chatId查询，仅确认不存在时清除该ID并新建专用只读会话；权限或查询失败会停止并保留ID，不删除其他聊天。

网页提供三步连接提示、启动/暂停按钮、复制固定指令与断连反馈。页面控制只记录本地意图，由插件获取并确认执行；页面不会将按钮点击误报为已连接。暂停时仍检查控制请求，不调用生成模型。

Operit增加`/storybridge start | stop | status`及精确中文管理短句拦截，避免明确管理请求进入故事生成。
