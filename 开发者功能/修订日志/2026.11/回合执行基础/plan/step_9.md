## P1 · 修正失效引用与不准确的技术说明

- **目标**：让每个指针都有现行来源，让技术约束与真实解析行为一致；不借此新增角色层级或剧情机制。
- **依据**：法典「细则字数见卷四」只有一个引用，运行资料中无卷四；角色中的「NPC社交层级」出现两次但无定义。普通 Python/JSON 字符串中的弯引号本身合法，真正风险是代码定界符冲突或错误转义。`narrative.vigilance`、`sys.vigilance` 正文含字面 `\n`，可读性差。
- **方向**：字数硬顶指向指南，写作节奏指向 `narrative.pace`；未定义层级先核对原意，再改为已有且确切的关系/场合规则。将引号说明改成定界符与转义要求，区分排版习惯和解析禁令；字面换行按 JSON 正确转义保存，使解析后的正文真正换行。
- **候选影响面**：`AGENTS.md` 的索引/速览、`txt文件/全局执行法典.md`、`txt文件/一键注入指南.txt`、`txt文件/知识库/角色类.json`、`叙事判断.json`、`系统标签类.json` 的指定段落；只处理本项命中的问题，不全库润色。敏感代码：不涉及。
- **依赖**：无；无法确认的旧指针不自行发明定义，留在该子项裁定。
- **验收**：程序指标＝候选范围内旧失效指针归零、四库能解析、条目 ID/key/关键词/常驻标记不变；复用已有引号实证，不新建测试套件。创作指标＝不改变人物身份、关系、情节或既有强弱倾向。
- **风险与回滚**：L1 / R1；未来执行时仅为实际修改的文件各留一份父版。风险是把未定义概念误当成应删除的设定，因此先确认其实际含义。本项不写正式快照与存档。

## P2 · 明确入口分支、叙事权限与数据合法性

- **目标**：让模型准确理解本轮应读什么、交什么，以及哪些事实不能凭文字自证。
- **依据**：主提示的唯一审计模板仍含「世界书已注入」，与桥接物理读取不符；故事模式的「进入后确认状态」缺少与裸 JSON/Python 输出的分支关系；「知识库 > 注入契约」容易被理解为叙事可以越过字段白名单和硬顶。`validate_system_log_scheme_a` 与 `_verify_audit` 能验证格式、读取覆盖和来源一致性，不能证明内容语义正确。
- **方向**：把维护/冷启动确认、桥接故事输出、手动故事输出分开；桥接只按真实读取填写来源，手动入口按实际注入或物理补偿记录。把冲突处理拆成两层：叙事意图与人物行为按叙事权限处理；节点结构、字段、字数硬顶和执行器限制始终合法，遇冲突重写表达。审计文本明确「程序已核实的事实」与「模型提出的语义判断」。
- **候选影响面**：`txt文件/提示词.md`、`全局执行法典.md`、`一键注入指南.txt`、`故事检索索引.md`，以及 `AGENTS.md` 对应索引。先对齐现行入口；本项不修改读取审计程序，自动装配归 P8。敏感代码：不涉及。
- **依赖**：建议在 P1 后实施；沿用现行 `reading_policy`，不提前取消必读要求。
- **验收**：程序指标＝同一入口只有一种合法输出说明，桥接模板无虚构注入声明，索引不复制权威条文。创作指标＝用「已物理读取但未注入世界书」「叙事要求碰到节点硬顶」「维护询问」三类普通案例审阅，均能确定正确分支；结构通过不得写成故事质量通过。
- **风险与回滚**：L1 / R1。风险是只改模板而遗漏其他入口承诺；定向检查对应声明即可，不重写全套规则。本项不写正式快照与存档。

## P3 · 按层次整理角色，并逐人处理冲突

- **目标**：保留人物辨识度，解除把默认倾向写成所有场景必然反应的约束。
- **依据**：角色正文共8,184字符；沈知韫1,961、苏婉青2,685、徐念薇2,096、徐承邺718、徐志北724。现有内容把身份事实、性格、习惯、阶段反应与表演建议混在同一层。
- **方向**：按「身份事实 → 稳定倾向 → 听话者/关系差异 → 当前状态来源 → 情境触发 → 表达建议」标明作用范围；当前状态仍取记忆，不固化进角色档案。外形条目中的行为建议回归行为层，不为压字数删人物信息。
- **逐人切口**：沈知韫先区分商业场合的凌厉与亲密关系中的自责，合并三处揉眉心为可选习惯；苏婉青界定成年人卸防后的俏皮与既定声线限制；徐念薇处理「内心温柔、减少疏离」与恒定半步距离、无情绪、不言语、不红眼眶的绝对措辞；徐承邺将工具人/环境锚点定位与人物自身动机分开。徐志北保留玩家控制边界，不替玩家发明关键行动。
- **候选影响面**：主要是 `txt文件/知识库/角色类.json`；涉及身份或驻地来源时只修相应指针，不擅改世界观或关系事实。可按上述四位角色分成 P3 的子项逐一处理。敏感代码：不涉及。
- **依赖**：P1、P2；人物实质取舍只在该角色子项中确定，计划阶段不替宿主定新性格。
- **验收**：程序指标＝角色条目数及非 content 元数据不变、身份/年龄/亲属关系/秘密知情范围不变、同一事实有唯一来源。创作指标＝普通事务、放松交流、意见分歧可呈现差异反应，习惯动作可省略；不因松绑而把三位角色写成同一种俏皮声线。审阅小样不写入剧情。
- **风险与回滚**：L1 / R1。风险是去掉绝对词后削弱人物底色，因此先展示该人物候选段落与保留点，再按选定范围实施。本项不写正式快照与存档。

## P4 · 消除设定与指导之间的相互牵制

- **目标**：让情境决定反应与节奏，保留角色自主性、日常交流和真实情绪。
- **依据**：中性保护与角色预设的强烈反应竞争；`sys.breakout` 容易把连续日常当成必须打断；去水检验可能误删玩笑、安慰和关系确认；「禁止连续三句标签开头」与特定状态下「有台词一律前置标签」冲突。
- **方向**：默认倾向不替代当轮事实；无触发依据不强制升级。破局按实际停滞或重复处理，不因日常本身强插事件；玩笑、安慰、试探只要承担人物或关系作用就可保留。明确台词声学规则的条件和例外，不让多条通用禁令同时管一处。P4 处理规则含义，供应商映射与代码范围留给 P6。
- **候选影响面**：`txt文件/全局执行法典.md`、`知识库/叙事判断.json`、`知识库/系统标签类.json` 的相关条目；角色侧已由 P3 确认的边界只作引用。敏感代码：不涉及。
- **依赖**：P2、P3；涉及「连续几轮」「何时归零」的具体标准须先在本项定语义，再交 P9 实现。
- **验收**：程序指标＝相关通用规则有清楚作用范围和例外，无同条件下相反指令。创作指标＝日常可以自然延续、冲突有事实触发、人物可开玩笑或安慰，不会为满足机制忽然转性；用日常/分歧/停滞三个短场景审阅，不创建正式回合。
- **风险与回滚**：L1 / R1。风险是过度松绑导致无推进；保留情境因果与功能要求，不采用一律放宽。本项不写正式快照与存档。

## P5 · 为日常对白建立情绪表达与人工验收方法

- **目标**：让卖萌、撒娇、急迫、生气等情绪在措辞、节奏和接话方式中成立，同时保持成年人物的表达差异。
- **依据**：当前规则主要限制卖萌，积极的日常情绪指引较少；已存对白样本没有声学标签，只能证明语气信息没有进入该句标签，不能证明音频必然平淡。文字自然度与声音表现必须分别判断。
- **方向**：写清允许自然短答、改口、省略、未完句的使用条件，补足日常轻松与幽默的表达空间。小样用于验收，不成为每轮必读、必须套用的台词模板；不强迫每句话带标签。
- **候选影响面**：`知识库/叙事判断.json` 的对白条目，必要时与 P3 的角色表达边界对齐；验收小样仅存开发记录，不进入常驻规则。敏感代码：不涉及。
- **依赖**：P3、P4；与 TTS 验证分开，可先完成文字审阅。
- **验收**：程序指标＝样本节点合法、硬顶合规、正式存档未变。创作指标＝建议先审6条小样，覆盖三位角色；需要完整对照时扩到「三位角色 × 四种情绪 × 两档强度」共24条，均用普通生活情境。对自然口语、角色辨识、情绪贴合、接话连贯各按0/1/2分记录；分数是人工比较工具，不声称程序能判定活人感。出现设定冲突或代替玩家关键行动必须修正，是否接受表达由宿主阅读判断。
- **风险与回滚**：规则 L1 / R1；新增验收材料 R0。风险是示例固化或过度表演；验收中同时保留平静对白作为参照。本项不生成正式剧情、不写正式快照与存档。

## P6 · 明确逐句语气范围，再建立语音供应商适配

- **目标**：使当句需要传给 TTS 的语气明确、可追踪，模型不必记忆供应商标签和跨请求规则。
- **依据**：前端只发送当前 `node.text`，相邻旁白的「带笑」「急着追问」不会进入该请求；各节点独立请求，不能假设声线自动延续。`emotion` 被配置归一化清空。Fish 官方文档本轮两次访问失败，`urgent/playful/pouting` 等候选词不代表已证实支持。
- **方向**：先锁定「语气属于当前句、默认不跨请求继承」；拟让模型表达少量明确的语气语义，由适配层映射已证实有效的供应商标签或能力。若需可选语气字段，须在本项实施契约中先确定字段名、枚举、默认值、冲突优先级和旧节点兼容，再同步节点白名单与服务契约。未验证的标签不进入已支持清单；未知语气保留可读台词并记录原因，不凭旁白自动猜强烈情绪。
- **候选影响面**：`txt文件/一键注入指南.txt`、`知识库/叙事判断.json`、`story_service.py` 的输出契约、`round_runtime.py` 的节点校验、`voice_client.js`；若涉及前后端处理，还包括敏感区 `main_template.html`、`语音运行.py`，须明确授权。确切最小目标集在接口设计后锁定。
- **依赖**：P5 的语义边界；供应商能力需可访问文档或隔离实测。未验证能力不以规则措辞代替验证。
- **验收**：程序指标＝同一句台词从节点到请求不丢字，语气只影响目标句，旧纯文本节点可用，Fish/显式 Edge 分支按各自能力处理，服务校验与字段同步；合法性不靠静默删除内容实现。创作指标＝同文本有/无语气的隔离试听确实能听出预期区别，且不损伤角色声线。没有音频证据则该能力仍记待验证。
- **风险与回滚**：L2 / R1，可能涉及节点接口和敏感代码；旧数据只读兼容，不原地改存档。风险是标签不受支持或字段与校验不同步。本项维护期间不写正式快照与存档。

## P7 · 用同文本对照判断角色语音参数

- **目标**：判断语音参数是否压缩表现空间，基于听感决定是否调整。
- **依据**：苏婉青当前 `temperature=0.5 / top_p=0.06 / repetition_penalty=1.44`，与另两位角色的 `0.72 / 1.0` 等配置明显不同；差异不能直接证明声音平淡，需对照试听。
- **方向**：固定文本、音色、模型与语气，一次只变一个参数；先少量对照，确有差异再扩大样本。记录可复现条件和失败请求，避免同时改文字、标签和采样参数。确认结果后才经现有语音管理/服务入口保存；不手写 `voice_config.json`。
- **候选影响面**：试听记录、临时音频与现有管理入口；除非单项另行批准，不改语音管理页面或服务代码。调用真实服务的范围与样本数量在本项确定，本次计划不调用。
- **依赖**：P6 的标签/语气范围稳定，或明确选择无标签纯文本对照以隔离变量。
- **验收**：程序指标＝确认实际发送参数符合对照表、一次只变一项、原设置可恢复。创作指标＝宿主按自然度、情绪贴合、稳定性试听选择；随机生成差异不能直接当作参数因果，不保证每次合成一致。
- **风险与回滚**：只试听 L0 / R0；保存设置 L1 / R2，以选中字段的原值表为唯一配置回滚凭据，通过同一管理入口恢复。若需修敏感代码另列目标，不能借试听扩大范围。本项不写正式故事快照与存档。

## P8 · 自动组装请求身份、事实审计与事件清单

- **目标**：模型只产出必要的故事语义与事件判断，确定性封装和重复记账交给程序。
- **依据**：`prepare` 已提供 `memory_layers` 与 `summary_sources`；请求身份、来源指纹、工具调用和读取覆盖有真实会话记录；目前部分信息仍要求模型重复填写。七段 SYSTEM_LOG 通过只证明格式，不证明理由真实。
- **方向**：请求标识、回合/版本等取可信请求上下文；契约允许的固定空字段由程序组装，缺失的必需语义不得自动补空。工具调用次数、读取覆盖、来源指纹、记忆层数量从真实记录派生；事件清单从已校验的结构化事件派生。模型继续负责意图理解、人物/因果判断、事件是否成立及摘要的重要性；其判断不能自动盖上「通过」。
- **候选影响面**：`story_service.py`、`round_runtime.py`、`txt文件/提示词.md`、`一键注入指南.txt`；若需改引擎审计存储，`injection_core.py` 属敏感区，单项明确授权。节点内容与数值算法不在本项调整。
- **依赖**：P2；先把每个审计字段标为「程序事实」或「模型判断」，再改封装。P10 后可复用统一注册表，不等 P10 也可沿用当前白名单。
- **验收**：程序指标＝自动字段与真实回执/请求身份一致，重复请求不重复提交，过期版本和未读取来源仍拒绝，缺失语义仍报错；比较模型原先手写的确定性字段数量与自动派生后的数量。创作指标＝保留无法由程序证明的语义说明，不把格式 PASS 升格为质量 PASS。
- **风险与回滚**：L2 / R1。风险是为了自动化而伪造审计或绕过验证；所有派生字段必须有可追踪来源。本项使用隔离请求验证，不写正式快照与存档。

## P9 · 让微状态有效期与回合计数真正由程序执行

- **目标**：消除「文档承诺自动、实际仍靠模型记账」的落差。
- **依据**：`update_micro_states` 只更新显式布尔值，省略会保留旧值，无到期；`update_counters` 只保存模型给的数字，递增、归零、触发仍由模型承担。
- **方向**：先为每个状态/计数器列出进入条件、维持条件、到期/退出条件、更新时点和归零条件；模型只交需要语义判断的事件或条件，程序负责确定性计数与转移。按规则分别使用回合数或剧情时间，不凭名称猜有效期。提交失败、重试、取消不计为成功回合；旧存档缺少期限元数据时的处理需明确，不能批量默默清空或补造时间。
- **候选影响面**：`injection_core.py`（敏感区）、`round_runtime.py` 及指南/系统标签相应条目；若序列化需要变更，在该项契约明确兼容方案。本计划不批准迁移正式存档。
- **依赖**：P4 确认触发语义；P8 的请求幂等性可复用。争议阈值先由宿主逐点裁定。
- **验收**：程序指标＝隔离数据覆盖首次进入、条件持续、条件结束、到期边界、回合重试、失败提交与旧格式读取，计数每次成功提交只变化一次；指南承诺与实现一一对应。创作指标＝状态机不会自动判断人物意愿，不因固定计数凭空插入剧情。
- **风险与回滚**：L2 / R1（代码与规则父版）；若未来确需配置或数据迁移，另定 R2/更高风险契约，不在本项默认授权。维护验证不写正式快照与存档。

## P10 · 统一事件注册表，复用已有编号器

- **目标**：同一事件的合法标签和结算定义有唯一来源；模型不再自行记编号序列。
- **依据**：五类事件表共65个标签，分布为18/6/17/9/15；警惕系统另有标签，不能混入这65个的统计。当前白名单来自指南表格及代码 AST 提取，存在文档/实现分散维护风险。`_next_task_id` 与 `_next_item_id` 已能分配任务和道具编号。
- **方向**：设计一份机器可读的权威事件注册表，路径与字段在本项契约锁定；由它生成模型可见说明和验证白名单，结算逻辑引用同源定义，避免增加第二份手工清单。保留现有标签语义与数值；模型只选有事实依据的事件。任务和道具继续用现有分配器，不新增平行编号器。
- **候选影响面**：核准落点的注册表、`round_runtime.py`、`injection_core.py`（敏感区）、指南和系统标签的对应表述；编号入口仅在确有重复手填时对齐。
- **依赖**：P2；建议 P8 后实施，先清楚区分「事件判断」与「清单组装」。
- **验收**：程序指标＝五表65标签集合及已有数值结算等价，警惕标签另行对账，无新增重复权威；未知标签仍拒绝，生成说明与执行白名单一致，任务/道具编号无碰撞。创作指标＝事件仍由已发生正文事实支持，不从候选选项预结算。
- **风险与回滚**：L2 / R1；新增注册表单独属 R0。风险是迁移注册表时顺带改变公式或旧标签语义，因此本项只做同等行为的集中维护。本项不写正式快照与存档。

## P11 · 把关系事实与合法称谓做成可查询资料

- **目标**：减少反复推算亲属关系和默认称谓的负担，保留人物根据场合选词的自由。
- **依据**：同一关系信息散在角色、世界观和自称要求中；事实层与表达层混写容易重复，并触发机械自称。
- **方向**：先建立关系事实的唯一权威表示，区分血缘/法律或社会关系、谁知道什么、当前称呼对象；查询按说话者、听话者、场合返回合法候选及来源。模型选用何种称呼、是否省略称呼仍由人物情境决定；不自动把完整关系表塞进每轮输入。
- **候选影响面**：`txt文件/知识库/角色类.json`、`世界观类.json`、`故事检索索引.md`；若增加查询服务，具体入口与只读工具权限另在本项锁定，不默认修改敏感区。
- **依赖**：P3 已确认人物关系与听话者边界；P12 可复用查询结果与来源格式。
- **验收**：程序指标＝每个关系事实有唯一来源，查询有说话者/听话者方向，隐藏信息不会泄给无知情资格的角色，来源指纹有效。创作指标＝同一人物可在正式与放松场合自然换称谓，无须每句重复身份自称；身份事实本身不变。
- **风险与回滚**：资料整理 L1 / R1；若改桥接接口升 L2 / R1；新增可再生成索引属 R0。风险是把事实查询做成强制台词替换器。本项不写正式快照与存档。

## P12 · 在不删规则的前提下减少重复读取与包装

- **目标**：让模型看到本轮真正需要的权威正文和来源证明，减少 JSON 包装、无关条目及已由程序提供的数据重复。
- **依据**：下方字符基线显示四库包装约占38.7%，指南桥接段约占六份必读46.8%。当前桥接仍验证工具白名单、物理读取、行覆盖和来源指纹；只改提示让模型「不用读」会破坏真实审计。
- **方向**：按 key 从原库提取正文，附源文件、条目 key、当前版本指纹与完整性说明；缺失 key 或指纹失配明确报错，不能给空正文冒充成功。按入口提供相关指南，按需提供事件说明/关系查询；原始规则完整保留，不维护第二份手写摘要。物理读取与提取回执必须可核实，若改变审计方式，工具白名单、覆盖定义、读取策略和 `_verify_audit` 同步升级，不能仅凭自报元数据宣称已读。
- **候选影响面**：`story_service.py`、`round_runtime.py` 的上下文与审计入口、已核准的只读提取能力、`txt文件/提示词.md`、`故事检索索引.md`，必要时 `AGENTS.md` 索引；是否涉及桥接插件须在该项点名。现行必读顺序在新契约通过前继续有效。
- **依赖**：P2、P8；P10、P11 完成时优先复用其注册表/查询，未完成不为此复制内容。
- **验收**：程序指标＝提取正文与源条目逐字一致，缺失/陈旧来源被拒绝，审计能证明本次真实读取，按同一回合口径比较前后字符量、读取调用量、模型手填字段量和重试率。创作指标＝关键规则与相关人物/记忆未漏读，输入更少时仍能完成同一语义任务；不能只看字符减少就宣布质量不降。
- **风险与回滚**：L2 / R1；新增可再生成缓存/索引属 R0，并先补同步排除项。风险是节省包装时削弱来源证明或漏掉跨条目约束。本项维护期间不写正式快照与存档。

| 后续观察项 | 比较方法 | 质量约束 |
|---|---|---|

| 审计与结构 | 来源/版本拒绝、节点合法率、重试次数 | 结构通过不等于故事正确 |
| 状态与结算 | 同事件下前后结果、幂等提交、到期边界 | 不替人物决定意愿，不预结算选项 |
| 对白与声音 | 文字人工评分、固定文本隔离试听 | 保留角色差异，供应商能力有证据 |

## 逐项实施与交接方式

1. 宿主阅读后点选 P 编号，P3 可进一步点选人物；不默认一次批准全部项目。
2. 执行该项前重读相关现役段落，给出具体修改范围、敏感目标、必要的接口/语义裁定及定向验收；不因本计划列过候选文件而顺手改其他文件。
3. 范围确定后按 into/iter-revise 一次事务实施，先留足够恢复凭据，再写入并做必要验证；不为同一已批准范围反复请求确认。
4. 每项结果进入下一份成对的 plan/logs，项目规则要求的摘要进入开发者说明书；规则正文只保留运行所需内容，不夹带过程、版本补丁或测试对白。世界书导出仅在相应源项改变且该项列入清单后再生成，不默认导入平台。
5. 交付时报告改动、真实通过/未通过、未验证内容和恢复方法，再等待宿主选下一项。本计划完成后停在这里。

本步恢复级别：R0，纯新增；需要撤销时只删除本计划及对应交接单，不触碰 step_8 和现役文件。实施各项所需的备份与精确恢复命令留到该项契约锁定时生成，本次不提前创建。
