## 1. 变更背景

玩家在实机体验中反馈了 5 项核心体验瓶颈，经技术审计与端到端链路分析定位如下：

1. **副模型无思考能力频繁报错**：部分轻量副模型（如无思考槽或低算力模型）在后台提取复杂多档事件标签时，因缺少 CoT 思考推理导致 JSON 格式截断或事件对象错填（如误将监视者填为被监视人）；
2. **主角参与感过弱**：此前为防止 AI 越权代写，对徐志北发言施加严禁代写硬锁，导致整段剧情主角常仅有一句话，缺乏自然的具身动作反应与呼应；
3. **结算时屏幕闪烁与重新刷新出戏**：副模型结算期间前台重绘清空 DOM（`innerHTML = ''`），并在结算成功或重试返回时发生画面跳动与动画重播，破坏沉浸感；
4. **免费档语音等待时间长**：Fish Audio 每次请求重复建立 TCP/TLS 握手，缺乏多句连续预热，点按下一句时需等待云端生成；
5. **角色动作与台词形式混淆**：此前非主角动作与台词采用相同的大头像排版，不注意看容易误将动作描写当成角色在说话。

## 2. 核心架构与改动实现

### 2.1 副模型结算思考自适应与重试自动提权（Issue 1）
- **三档思考控制模式（`settlement_thinking_mode`）**：
  - `auto`（智能自适应，推荐默认）：首跑采用无思考极速生成，若遇格式或事件校验错误，在第 2/3 次原地重试时**自动提权开启深度思考（`enableThinking: true`）**；
  - `off`（常关，极速）：全程关闭思考，适合高算力指令微调模型；
  - `on`（常开，深度）：全程开启思考，适合长推理链路模型。
- **全链路参数与指令下发**：
  - 桥接插件 [`main.js`](../../scene_chat_dev/local.story.operit_bridge/main.js) 新增 `effectiveSettlementThinkingMode(config)` 计算逻辑，支持 `/storybridge thinking <auto|off|on>` 斜杠命令；
  - 原生 Compose DSL 设置界面 [`ui/settings.ui.js`](../../scene_chat_dev/local.story.operit_bridge/ui/settings.ui.js) 升级为 3-chip 快捷选择器；
  - 后端 [`story_service.py`](../../story_service.py) 在 `POST /api/story/bridge/control` 与 `POST /api/story/preferences` 支持思考模式配置并持久化至 `.round-runtime/story/prefs.json`。
- **机器针对性修复提示**：
  - [`story_compiler.py`](../../story_compiler.py) 在 Stage 2 `build_settlement_spec` 规则 3 增补 `⚠️【监视目标防错铁律】`（监视目标严禁填监视者徐承邺本人，必须填被监视受害人）；
  - [`story_progression.py`](../../story_progression.py) 在 `监视事件目标无效`、`事件对象不在本段实际场内` 与 `事件必须引用本段实际正文` 时注入针对性机器修复提示。

### 2.2 主角主权忠实演绎与静音沉浸闭环（Issue 2）
- **演播偏好双模式（`protagonist_style`）**：
  - `faithful`（忠实演绎，默认）：前台开场必须通过 1~2 句 `[A:徐志北]` 或 `[N]` 具身落位，中段保持自然微反应，且允许输出最多 2~3 句严格贴合玩家原意图的简短 `[D:徐志北]`（单句 ≤40 字、严禁越权承诺或升级档位）；
  - `silent`（仅动作感官）：严禁输出 `[D:徐志北]`，仅允许动作与内心微反应。
- **徐志北永久静音铁律**：
  - 无论何种模式，徐志北发言在服务端 [`story_compiler.py`](../../story_compiler.py) 与桥接端 [`main.js`](../../scene_chat_dev/local.story.operit_bridge/main.js) 均强制剥离 Fish 声学标签，前端保持严格 4 角色发声白名单（仅三女主与旁白发声），对徐志北对白发出 **0 次** `/api/tts` 请求。
- **偏好持久化**：
  - 新增 `POST /api/story/preferences` 与前端设置面板主角风格切换器，落盘至 `.round-runtime/story/prefs.json` 跨重启保持。

### 2.3 暗金星盘沉浸幕布与增量 DOM 补丁（Issue 3）
- **暗金沉浸星盘幕布（`#stageCurtain`，默认开启）**：
  - 当任务进入 `settling` / `settling_retry` / `settling_failed` 时，自动升起带微光磨砂与旋转星盘的暗金帷幕，柔和遮罩正文舞台并展示沉浸状态文字；副模型结算完成且新段落就绪后优雅淡出，**彻底消除结算重刷闪烁与失败跳动**；
  - 提供 `curtain`（默认）与 `stream`（原始实时流）双模式显式切换。
- **`patchMessageTimeline()` 零闪增量 DOM 补丁**：
  - 彻底废弃暴力 `innerHTML = ''` 重绘；基于 `dataset.renderKey` 识别同名节点并就地更新预览状态（`syncPreviewChrome()`），保持 DOM 身份与滚动条位置绝对稳定；
  - 进场动画 `.msg.is-fresh-enter` 仅对全新插入的末尾节点触发，杜绝历史节点反复触发 `msg-arrive` 动画。
- **单请求补步（`catchup: true`）**：
  - 玩家在流式期间超前阅读时，`catchUpPlayback()` 附带 `catchup: true` 单请求补发游标，跳过中间无谓预热，平滑接管。

### 2.4 Fish Audio 极速提速、Session 复用与滑动预热（Issue 4）
- **`requests.Session()` 长连接池复用**：
  - [`语音运行.py`](../../语音运行.py) 全局维护 `_FISH_HTTP_SESSION`（`pool_connections=4, pool_maxsize=6`），通过包装函数保持测试 monkeypatch 兼容，彻底消除重复 TCP/TLS 握手（单次提速 300~500ms）。
- **40MB 本地磁盘 LRU 缓存（`.cache/tts_audio/`）**：
  - 建立二级磁盘 LRU 缓存，配合 64 条内存 LRU 使得跨重启热点台词零延迟直出。
- **极速声学参数**：
  - 默认启用 `latency: "balanced"`，分块长度缩短至 `chunk_length: 180`（旁白 200），首包响应延迟压低至极致。
- **429 智能指数退避冷却（`_record_fish_429` / `_record_fish_ok`）**：
  - 触发限流时自动进入 4s~32s 退避冷却，阻断无效高频重试保护账号。
- **闲置滑动窗口预合成（`POST /api/tts/prefetch` + `schedulePrefetchWindow()`）**：
  - 演播推进或流式到达时，自动利用闲置并发槽（`TTS_PREFETCH_SLOTS=2`，100ms 快速超时放弃以防与实时播放争抢）批量向后预合成接下来 3 句台词，播放到下一句时直接命中缓存毫秒级发声。

### 2.5 动作与对白结构化视觉分流（Issue 5）
- **结构化排版与样式解耦**：
  - 非主角动作（`.msg.action:not(.player)`）：彻底移除大头像肖像与沉重的「凝视 ◉」按钮，采用通栏点线舞台带（`.action-strip`）+ `18px` 行内微头像徽章（`.action-mini-avatar`）+ 纯正宋体 Serif 排版（杜绝 CJK 伪斜体硬倾斜导致的文字变畸）；
  - 角色对白（`.msg.dialogue`）：保留 `38×46` 独立头像肖像、实心气泡、左侧 `3px` 角色专属重音条与轻量 `「」` 引号线索；
  - 玩家角色动作与发言（`.player`）：独立采用暗金边框与斜体括号高亮；
  - `[D:角色名]` 纯台词硬锁：严禁夹带 Markdown 外层引号或“她端起杯子抿了一口：”等动作神态叙述。
