# 深渊天平引擎 · 开发者说明书

> 文档性质：仅供项目维护、审查、迁移和开发决策使用。
>
> **本文件不得作为AI常驻规则、世界书条目、运行时知识库或每回合提示词注入。**
>
> 工作区根目录：`/storage/emulated/0/互动对话项目/Gemini网页版`
>
> **历史变更已归档**：本文件只保留当前有效的职责边界与流程（§1–§5）。变更历史统一见 `开发者功能/修订日志/`（按月整合归档）：2026-08 见 `修订日志/2026.8/2026年8月修订日志归档.md`，2026-09 见 `修订日志/2026.9/2026年9月修订日志归档.md`。

正式互动读取覆盖不要求平台返回文件尾空白，所有非空正文保持严格核验；缺正文由同任务一次补读完成。会话默认持续沿用，连接面板可选择重启服务后新建/每新行动新建及手动重建；换模型/存档仍隔离。旧聊天保留，失败草稿不成为事实，付费重试保留上次错误。

普通行动与SYSTEM按预扣kind生成各自条件契约，付费澄清也提供完整七字段conditions对象；不猜补缺失语义。地点别名由互动运行配置唯一维护，移动识别和校验使用同一解析函数，已解析操作及玩家原文依据直接传入生成信封。

## 1. 文档目的

本说明书承载运行规则之外的开发信息，避免把版本迁移、删除原因、兼容说明、事故复盘和维护流程重复注入AI上下文。

AI运行时只应读取各权威运行文件中的当前有效规则；开发者需要了解"为什么这样设计、从哪里迁移、旧版本如何处理"时，查阅本说明书或修订日志。

## 3. 知识库与entries产物规则

1. 只修改`txt文件/知识库/`下对应的源JSON。
2. 不直接手工修改合并后的`entries.json`或Operit导出。
3. 修改源JSON后，重建Operit导出（`Operit世界书导出/convert_to_operit.py`）。
4. 重建后检查条目数量、名称唯一性、关键词、常驻状态和JSON可解析性。
5. 不在源JSON条目中写入迁移过程、版本历史或开发者解释；当前有效结论直接保留，过程记录写修订日志。
6. 知识库关键词与正文改动，须同步`开发者说明书/世界书关键字配置.txt`与Operit导出，避免清单漂移。
7. 后端契约相关改动（标签名、固定字符串、引擎行为）须先核实`injection_core.py`实际结算逻辑，再改KB表述，防止「KB文本承诺与后端实现分叉」。

## 4. 规则修改流程

### 修改前

1. 阅读`AGENTS.md`和本说明书相关章节。
2. 用绝对路径确认目标文件；先用`rg`定位重复声明和上下文。
3. 判断目标内容属于运行规则还是开发说明。
4. 确认唯一权威文件，避免双源维护。
5. 记录拟保留、拟移动、拟删除内容，等待用户确认删除性改动。

### 修改中

1. 一次只修改一个职责边界或一个文件组。
2. 不改变未授权的接口、字段名、世界书名称或关键词（引擎参数扩展须向后兼容）。
3. 不把开发者说明书路径写入AI运行规则，除非运行时确实需要它。
4. 按`into`对实际改动的现役文件只留一份可核验父版。事务结束后，将同目录临时父版收至`开发者功能/归档/项目清理/历史修改备份/`并保留原相对路径，清单记录目标和恢复路径；不将开发备份写入运行/平台管理的`.backup/`或`.operit/backups/`，不在正式目录堆叠旧源码。
5. 对迁移内容记录来源、目标、日期、原因和验证结果。

### 修改后

1. JSON执行解析检查；Python执行语法检查（不执行真实存档写入）。
2. 检查条目数量、名称唯一性、常驻数量和关键词变化。
3. 测量修改前后的字符量（控制token增量，规则改动优先去除/修改而非追加）。
4. 做短回合、双角色回合和复杂事件回合的模拟验收；涉及引擎改动须跑批量注入回归。
5. 将结果记录到修订日志；本文件变更记录追加一行摘要。
