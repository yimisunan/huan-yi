# 世界状态与行动契约审阅稿

状态：阶段C设计交付，供审阅，未实现新世界账本、资源消耗或主窗口替换。上游：主窗口接入调整计划.md、交流消耗与结算讨论记录.md。24不作为本项目任何默认值。

## 一、接受单位与唯一事实源

一次请求有request_id、input_hash、base_world_revision、scene_id、source_version和cost_policy_version。重交同ID同内容返回原回执；同ID不同内容拒绝；旧版本结果不接受。

交流消息、合法状态变化、消耗、读取审计和接受回执在同一事务中提交；成功后world_revision递增一次。消息序号、世界版本、阶段编号和游戏日期各自独立，不复用CURRENT_ROUND表达全部概念。

候选正式账本使用SQLite，现有文本存档在隔离导入通过后作为兼容投影，不再有第二个写入器。正式切换前仍以现役RoundStore管理的原文件为权威；新设计仅在副本内验证。不能让旧执行器和新账本同时写同一世界。

建议实体表：world_meta（日期/时刻/阶段/政策版本）、characters（身份和当前位置）、resources（角色资源）、items/ownership、tasks、messages、claims、facts、knowledge、commitments、requests、receipts、source_versions、read_audits。静态人物卡仍来自原知识库，不复制进动态账本形成第二套设定。

## 二、事实与知识

每条记录带record_id、kind、subject、predicate、value、evidence_message_ids、origin及known_by。程序只接受已登记实体、操作和有效证据ID；私有推理不写成公开事实。

| 类型 | 含义 | 例子与处理 |
|---|---|---|
| claim | 人物陈述，未核实 | “分公司亏损是哥哥造成的”不等于确认责任 |
| belief | 角色相信的内容 | 只属于该角色，不自动对其他人可见 |
| commitment | 明确承诺 | 保存承诺及状态，不提前写成已履行 |
| fact | 已确认的世界事件/状态 | 由合法操作、导入来源或明确披露形成 |
| knowledge | 某角色取得某条信息 | 单独校验传播途径与在场/通信对象 |

秘密披露必须有secret_id、说话人知情资格、实际听众、证据消息和当前允许披露的规则依据。现阶段未定义的披露条件走待处理，不让模型仅凭“现在气氛合适”解锁。明确披露规则本身需审阅，不永久禁止剧情发展。

事实变化会反过来约束最终显示文本。若正文宣称移动/赠送/秘密公开而操作无法通过，整份结果不得作为正式剧情接受；不能只删状态增量、留下已经发生的正文。

## 三、消耗政策

基础量B、交流阈值Q、轻/持续行动成本表、恢复规则与角色资源上限全部为待定配置，缺配置时禁止正式启用，不以0或其他游戏数值静默代替。资源量使用非负整数单位，游戏耗时单独使用整数分钟。

每条正式接受的玩家输入扣一次B；所有选项与自定义输入相同。没有行动的回应、澄清和拒绝若作为有效交流被接受，也扣B；技术失败和同请求恢复不扣。界面显示该约定，避免把故障算作玩家消耗。

行动成本由程序按操作模板和已校验规模查表，模型只提出action_code、参数、证据和候选tier；模型填写的数值不进入结算。tier不符查表结果则拒绝计划或重新询问，不自动执行更贵版本。只有实际执行的操作收行动成本，失败尝试是否收费在对应模板定义。

| 等级 | 范围 | 状态变更 |
|---|---|---|
| exchange | 接话、询问、表达态度 | 仅交流和陈述/承诺，无实际行动自动完成 |
| brief_action | 单个已支持的小范围行动 | 明确实体、地点、范围，成本查表 |
| sustained_action | 持续或跨地点行动 | 明确规模/耗时，必要时先确认计划 |
| unresolved | 未支持、歧义或多项重大意图 | 不执行行动，澄清或拆分 |

不按文字长短收费；同样的行动不能因简写而便宜。一次自定义输入可表达多个意图，但首版最多执行一个明确行动单元；多操作仅在同一已登记原子模板中允许，如一次交付同时扣库存并改归属。其他组合拆成行动队列，执行前告知范围，不能静默选第一项替玩家决定。

额度不足不发起可预知无法支付的执行请求；生成后才发现不足则保留未接受计划，不显示已执行的正文。基础B与行动成本一起预检、一起扣除。高消耗不保证成功、不购买他人同意、不绕过人物能力和知识边界。

## 四、选项与自定义输入

A/B/C仅为位置，实际使用稳定option_id、scene_revision、label、action_template、参数边界、tier、cost_policy_version、expires_on_revision。选项由程序校验后才可点，成本标识由程序生成，不相信模型附带的数字。旧选项过期不可执行。

自定义输入不另建分类模型，现有主模型同次回复提出受限计划。明确闲聊直接回应；重大/不明确行动返回proposal，说明范围与程序核定的成本，玩家确认后执行。确认使用proposal_id和独立执行request_id，预览不重复扣交流基础量；预览生命周期、取消与修改均不执行世界动作。执行时重核版本与资源。此流程仅重大行动需要，不能每句聊天都加确认弹窗。

首版操作候选：record_claim、record_commitment、move_character、transfer_item、advance_time、rest、update_task、disclose_secret。后五类及任务发放的规则未审定前保持关闭，不能仅注册名称就算支持。既有事件注册表中数值结算尽量适配复用，不让模型直接patch数值。

## 五、阶段、日期与上下文

交流累计量达到Q触发阶段边界提示/整理，不强迫世界跳日或角色睡眠。跨日由游戏时间经过日期边界触发；体力不足触发休息约束，二者不等价。

每条消息与事实已耐久保存，阶段整理只生成索引和事实汇总，不是第一次写存档。无新增事实可记录“本阶段无新增确认事实”，保留交流、未履行承诺与未答问题。仅重建模型会话不增加阶段、日期或扣资源。

上下文从当前状态、相关事实/知情、未完成事项、最近消息和必要原文构建。旧原文保留可补查；不因摘要遗漏删原记录。先用确定性索引，不增加后台摘要模型。长程压缩与24次限制调整留到阶段G。

## 六、旧存档映射与迁移验收

| 旧源 | 导入目标 | 约束 |
|---|---|---|
| 全局记忆库 | 状态/位置/记忆原文/任务与条件 | 保留原段与来源，不凭摘要补事实 |
| 道具图鉴 | 道具定义、归属、有效条件 | 临时倒计时先保留旧单位，不擅自换算分钟 |
| 次要NPC名册 | 登记实体与原始档案 | 同名去重须有依据，不能只看显示名合并 |
| data.json | 旧回合展示快照 | STORY_NODES不自动变为新增事实，旧选项默认过期 |
| 静态知识库 | 引用原源及指纹 | 不复制维护人格、世界观、关系事实 |
| scene_chat实验账本 | 默认保留独立实验记录 | 不自动并入正式世界；用户指定后另做事实审定 |

导入只读源文件→隔离候选账本→逐字段核对→验证恢复与重启→明确唯一写入器→批准后切换。解析不了的内容保留为unresolved_source阻止依赖行动，不让模型猜。SQLite与兼容文件不宣称跨系统原子提交：账本事务提交后按revision生成可重建投影，投影失败可重试但不重执行行动。

## 七、必须通过的检查

相同请求重复提交、断线结果重送、旧世界版本、源资料变更、资源不足、分类不明、多行动、选项过期、正文与操作矛盾、秘密越权、跨日与休息分离、投影中断与恢复、旧存档导入一致性。缺乏语义依据的操作不能因为结构合法就放行。

待审阅决策：资源名称与具体数值；第一批支持的行动模板；秘密披露条件；阶段边界是否强制整理后继续。先锁定这些，再实现隔离迁移；本稿不授权正式切换。
