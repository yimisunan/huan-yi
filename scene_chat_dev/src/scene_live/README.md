## 从旧存档继续

1. 点击顶栏「存档状态」，查看已导入的人物所在、数值、道具、任务和记忆；每项可展开来源原文。首次使用或旧源变化时点击「读取旧存档／重新读取旧存档」。这只创建隔离副本，不发模型请求。
2. 点击「在徐家主宅与沈知韫继续」。程序按玩家存档地点选择同地已登记人物，不用手填地点。当前徐志北、沈知韫在徐家主宅；徐念薇在工作室，苏婉青在市中心顶层公寓，暂不支持在此入口移动或远程交流。
3. 确认Operit桥接运行，再输入并发送。模型资料包包含绑定版本的位置、经核查共同知情的旧记忆和对应私有状态。当前餐厅一回合记忆已核查为徐志北与沈知韫共同知情；其他角色不能自动取得该记忆。
4. 刷新或重新启动服务后从本地恢复同一版本。旧存档变化时停止该版本的新交流，仍可看记录；重新读取后开启新存档场景。旧实验聊天不会自动变成世界事实。

维护检查：连接信息中scene_protocol为3、world_state_protocol为1。若只出现消息协议而没有世界状态协议，需重启Python服务加载scene_world.py与更新的scene_chat.py。

## 原实验与消息恢复

「场景管理」可恢复已有记录，或另外建立一至两位人物、手填地点的独立实验场景；列表区分存档交流与实验。创建场景不调用模型。已接受回复分为对白气泡、人物动作细竖线和无头像旁白，按原顺序进入同一消息流；点击人物可查看三张原立绘。

交流记录由.scene-chat/state.sqlite3保存，导入原文及不可变版本由.scene-chat/world/state.sqlite3保存；浏览器只保存场景ID、草稿与待确认请求。清理浏览器缓存不会删除服务记录，但可能丢失未送达草稿和请求身份。运行目录已排除自动同步。

连接故障先「查询原消息状态」；服务未登记时才显式「按原编号发送」或「放回草稿」。失败可「重试原消息」，仍用同一编号，技术失败不自动重试；来源或版本已变则保留记录并建立新场景。已成功消息不用重发。

当前仍为隔离普通交流：24次接受交流、160000字节资料包边界沿用；24不是资源或时间规则。action为场内表现，handoff为未执行事项；世界行动、资源消耗、秘密解锁及主窗口正式切换尚未启用。B候选页暂没有语音控件，原/scene-chat保留手动播放。
