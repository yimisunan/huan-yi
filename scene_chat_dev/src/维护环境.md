# 维护环境（proot Alpine）说明

本文件记录 Operit 维护终端的可用状态、一次性安装步骤和已经踩过的坑。目的是新窗口接手时不用重新试探环境，直接照抄命令。

## 1. 两套运行环境不要混淆

| 环境 | 用途 | 入口 |
| --- | --- | --- |
| Pydroid3（用户实际运行） | 跑 `语音运行.py`、Flask 服务、真实互动 | 用户在手机 App 里启动 |
| proot Alpine（维护终端） | 跑测试、构建插件、读写 Git、诊断 | `super_admin:bash` |

维护终端能读写项目目录（`/storage/emulated/0/互动对话项目/Gemini网页版`），但不是用户运行环境；测试通过不等于真机跑通。

## 2. 一次性安装（proot 被重置后照做）

```bash
apk add --no-cache git openssh-client py3-pip curl jq rsync zip unzip findutils grep coreutils
python -m pip install --break-system-packages flask requests
```

说明：

- Alpine 自带的 `python` 没有 pip，必须先装 `py3-pip`。
- Alpine 的 Python 视为「外部管理」，pip 必须加 `--break-system-packages`，不要用 `--user`（会造成路径分裂）。
- 项目只依赖 `flask`、`requests`（`werkzeug` 随 flask 安装）。其余 import 均为标准库。

装完用下面的命令自检，全部有路径、版本非空即可：

```bash
for c in python node git ssh curl jq rsync zip unzip grep find; do printf '%-7s %s\n' "$c" "$(command -v $c || echo MISSING)"; done
python -c 'import flask, requests, werkzeug; print("deps ok")'
```

2026-11-21 实测基线：Python 3.14.5、Flask 3.1.3、requests 2.34.2、Node v24.18.1、git 2.54.1、OpenSSH 10.3p1。

## 3. 之前反复碰壁的原因

1. **`pip: command not found`** → 没装 `py3-pip`。连带后果是 12 个 Python 测试在 `import flask` 处直接报错，看起来像“整套测试都坏了”，其实只是依赖没装。
2. **busybox 的 grep/find 是残废版**：`grep --exclude-dir`、`find -size 3M` 直接报 `unrecognized option` / `invalid number`。装 `grep` 和 `findutils` 两个包后就是 GNU 版本。
3. **没有 `curl`** → 想探网页/接口状态时只能绕 `wget` 或 `git`。已安装。
4. **ssh 的 home 不是 `$HOME`**：`ssh` 读的是 passwd 里的家目录（本容器是 `/root`），而 shell 变量 `HOME=/home/operit`。把 `config`、`id_ed25519`、`known_hosts` 写在 `~/.ssh`（= `/home/operit/.ssh`）会**完全不生效**，表现就是“公钥明明加了却一直 Permission denied”。正确做法见下一节。
5. **仓库旧配置 `credential.helper = gh auth git-credential`**，但容器里没有 `gh`，HTTPS 推送必然失败在 `gh: not found`。现在远端改用 SSH，不依赖 helper。
6. **测试需要 `scene_chat_dev/tmp/`**：多个测试用 `tempfile.TemporaryDirectory(dir=ROOT/'scene_chat_dev/tmp')`，清理掉目录后会 `FileNotFoundError`。该目录被 `.gitignore` 忽略，保留空目录即可，`run_tests.sh` 会自动创建。
7. **`/sdcard` 是 FUSE，IO 慢**：整套 Python 测试在项目目录约 15 分钟，`--fast` 拷到 `/tmp`（tmpfs）后约 13 分钟——差距不大，真实瓶颈是纯 Python 事务测试的 CPU 占用。跑整套前先想清楚是否只需要单个文件。

## 4. GitHub 推送（SSH）

私钥在容器的 `/root/.ssh/id_ed25519`（无密码短语），公钥已登记在账号 `yimisunan` 的 `Operit Android` 下。

```bash
# 首次配置（已做过，重装环境后重做）
mkdir -p /root/.ssh && chmod 700 /root/.ssh
ssh-keygen -t ed25519 -N '' -C 'operit-android@huan-yi' -f /root/.ssh/id_ed25519
ssh-keyscan -t rsa,ecdsa,ed25519 github.com > /root/.ssh/known_hosts
printf 'Host github.com\n  StrictHostKeyChecking accept-new\n  User git\n  IdentityFile /root/.ssh/id_ed25519\n  IdentitiesOnly yes\n' > /root/.ssh/config
chmod 600 /root/.ssh/config /root/.ssh/id_ed25519 /root/.ssh/known_hosts

# 自检（应返回 Hi yimisunan!）
ssh -o BatchMode=yes -T git@github.com

# 推送
git push origin main
```

- 远端：`origin = git@github.com:yimisunan/huan-yi.git`（旧仓库 `geni-eni-cra` 已废弃并移除）。
- `IdentityFile` 必须写绝对路径 `/root/.ssh/id_ed25519`，写 `~` 会按 `/root` 展开成不存在的文件。
- 想作废这把钥匙：GitHub → Settings → SSH and GPG keys 删除 `Operit Android`，本地删 `/root/.ssh/id_ed25519*`。
