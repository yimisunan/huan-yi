# 旧存档隔离接入说明

B页从旧存档继续时使用绑定的只读导入版本；旧RoundStore仍是正式世界唯一写入器。导入数据存在.scene-chat/world/state.sqlite3，现有交流仍存在.scene-chat/state.sqlite3。此轮没有正式世界切换，也不把交流的动作文字当作已执行的世界操作。

## 来源与映射

- 四份事实源：存档/全局记忆库.txt、徐志北道具图鉴.txt、次要NPC名册.txt，以及data.json；保存逐字节BLOB、SHA256及导入字段的原文行号。关系实体登记与知情映射也保存版本指纹；角色人格资料继续在原知识库维护。
- 当前位置只读最新区块，data.json.presence必须与之完全一致；面板保留整数/布尔及百分号、次数、等级的旧表示。历史面板不当作当前值。
- 道具只读活跃区，模板/过期区不作库存；ID、数量不明时不猜默认值，临时倒计时保留回合单位。NPC只导入完整范例之后追加的真实档案，不合并同名实例；当前“林秘书”只是范例。
- 任务、微状态、BUFF、计数器、监视、倒计时及生命周期保存原文；结构化任务无法解析时显示待确认。data.json只取展示元数据，不把storyNodes提升为事实，旧选项标记过期。记忆层回合与展示回合必须一致。
- 记忆保留完整原文；scene_chat_dev/src/legacy_visibility.json按单条原文指纹记录知情依据，无匹配时保留unresolved_source。当前唯一餐厅条目经逐段核查为徐志北与沈知韫共同在场，仅这两人能取得共同记忆。姓名出现不构成知情证据。

## 版本与故障

捕获源时复用RoundStore的线程锁及同一路径POSIX共享锁，不调用prepare/_recover，不发布旧文件。旧回合/新档有未恢复事务时直接拒绝导入。所有原文与派生状态同SQLite事务提交；导入失败不留下半个版本。来源相同重复导入返回同ID/版本；源变化创建新版本，旧版本保持可读。读取账本时核验payload、manifest和原文BLOB指纹。

存档场景固定world_id及world_revision，人物必须与玩家在同一旧存档地点，忽略用户手填实验地点。资料包加入该版本的在场位置、共同知情记忆、对应私有状态及玩家私有库存/任务，后两者不表示其他人物知情。全局原文、未核查记忆、缺席人物状态不整包注入。实验场景继续使用原路线，不必初始化旧源。

发送、重试与结果接受检查来源；旧源变动后保留旧消息与场景，暂停使用该版本，显式重导入后开启新场景。已有request_id的重复结果仍返回原回执，不再次入库。世界版本不会因闲聊增加，交流版本独立推进，未启用消耗。
